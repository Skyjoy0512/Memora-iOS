# 日本語Live音声会話

波形ボタンから開始する。約1秒の発話の区切りで選択中のAIへ自動送信し、
日本語の句点単位で読み上げる。回答中の発話は生成と再生へ割り込む。
中央のマイク/一時停止はLive全体を開始・停止し、スピーカーは読み上げを切り替える。
添付やモデルのシートを開くと一時停止する。途中の発話は既存の空の下書きにのみ残す。
添付・メンション・下書きがあるときは、Liveを閉じて通常の送信内容を確認する。

- Volocal b731963b の音声エンジン、パイプライン、文分割を部分移植（MIT）。
- Parakeet/PocketTTS/Qwenの英語用スタックは採用せず、日本語オンデバイス音声認識と
  日本語AVSpeechSynthesizerのPCMを共有AVAudioEngineで処理する。
- 認識はiOS 26のDictationTranscriber / SpeechAnalyzerを使用する。
  AssetInventoryで日本語モデルの不足を確認し、必要ならダウンロード・インストールする。
  prepareToAnalyzeでモデルを起動してから、有界の変換キューへマイクを接続する。
  旧SFSpeechRecognizerのsupportsOnDeviceRecognitionだけで準備完了とは判断しない。
- 認識した質問は通常のAsk AIへ送る。クラウドモデルなら認識済みテキストはそのAIへ送信される。
  録音ファイルは作らず、マイクのPCMをLLMプロバイダーへ送らない。
- リソース保護・録音の所有権・会話ID・ワークスペース世代を再確認する。
  書き込み承認や外部読み取りの既存制限は緩めない。
- 承認/質問カード中は認識を止め、画面上の承認/回答を待つ。音声で承認しない。
- 端末に日本語のオンデバイス音声認識がない場合は利用不可を表示する。
  Appleのクラウド音声認識へ黙って切り替えない。
- AIの未設定を開始前に検出する。登録モデルの独自エンドポイントは、そのモデル専用の
  キーチェーン項目を確認し、プロバイダーの標準キーとは取り違えない。
- 「聞いています」は認識の準備と実際のマイクバッファ受信を確認してから表示する。
  入力レベル表示だけが4Hzで更新され、会話やコンポーザー全体は更新しない。
  マイクのバッファ停止は3秒、入力音声に認識結果がない場合は15秒で理由を表示する。
  静かな待機、回答の生成・再生中、認識後の沈黙は認識停止と判定しない。
  認識エンジン自体の準備が30秒で終わらない場合も停止する（初回モデルダウンロードは別）。
- 発話ごとに認識器を置き換える。分析器の確定結果はフレーズ単位なので、確定した断片を
  蓄積し、次の可変断片と併せて表示する。約1秒の安定後に通常の送信へ渡す。
  前の分析器をキャンセルして終了を待ち、その後に次の分析器を起動する。
- 実機コンソールの`[Live]`は準備・入力受信・認識・送信・回答受信とエラーのdomain/codeのみ。
  発話本文、AI本文、音声、資格情報はログへ書かない。
- シミュレーターのボタン表示やコンパイルは、実際の音声・エコーキャンセル・AI往復の証明ではない。

## 検証

`bash tools/checks/run-live-conversation-checks.sh` は本番のLiveSentenceBufferと
LiveTurnAuthorityを使い、日本語/英語の分割位置、句点の直後の文字、長い空白なし文、
絵文字書記素、flushの重複拒否、割り込み/セッション置換後の古い結果拒否を検証する。

初回 `bitrig preview -platform iOS` はiOS 27.2 SDKで成功。
BitrigのiPhone 18 Pro MaxではLiveパネルへの遷移後、SFSpeechRecognizerの初期化が
`Failed to initialize recognizer` で失敗し、利用不可を表示して停止した。
日本語の発話→自動送信→AI→PCM読み上げ、話者による割り込み、イヤホン/Bluetooth、
端末の着信・録音競合、実音声中の承認カードは実機での検証が残る。

最終ビルドも `bitrig preview -platform iOS` で成功（iOS 27.2 SDK、既存の警告11件）。
Liveの本番ロジックチェック、既存コンポーザーの25個の中断/切替競合チェック、
チャット画面の構造チェック8件を通過した。最終版のパネルで日本語の利用不可案内、
再開/終了ボタン、通常画面へ戻る操作を確認した。実機の音声検証は未実施。

## 実機で認識結果が出ない問題への対応

利用者のiPhoneで「聞いています」のまま認識文字が出ないとの報告を受け、上記の
モデル準備と入力確認へ変更した。旧版の実機コンソールには認識の診断がなく、
マイク経路と認識器のどちらが根因だったかは確定していない。
LiveInputHealthの本番ロジックで、入力バッファ停止・認識無反応を検出し、沈黙・
認識後の待機・AIの生成/再生を誤検出しないことを検証する。
修正版の実際の発話→AI→読み上げの確認は、利用者のiPhoneでの再テストが必要。

修正版の検証結果:
- `bitrig preview -platform iOS`成功（iOS 27.2 SDK）。
- `bitrig build -destination generic/platform=iOS`成功。両方とも既存の警告11件。
- Liveの本番ロジックチェック、入力キューの所有権/順序/上限/停止チェック、
  コンポーザーのレイアウト・提案のプライバシー/下書き保護チェック、チャット構造8件が成功。
- 最終版のシミュレーターは日本語の分析器に対応する音声形式を返さず、理由を表示して停止。
  再開、失敗後の終了、通常入力への復帰を確認。音声会話の成功を示す検証ではない。
- iPhone用のビルドは作成したが、こちらから利用者のiPhoneへインストール/起動はしていない。
  Bitrigの「Run on…」による更新と、入力レベル・認識文字・返答の実機確認を依頼した。
