# Memora UX改善 実装指示（OpenCode向け・2026-09レビュー）

あなたはこのリポジトリ（SwiftUIのiPhoneアプリ「Memora」）を改修するエンジニアです。
下の UX01〜UX16 を **上から順に1項目ずつ** 実装してください。各項目の「現状」は
レビュー時点のコードで確認済みの事実です。

## 0. 前提ルール（必ず守る）

- 作業前に `AGENTS.md`・`DESIGN.md`・`docs/IMPROVEMENT_BACKLOG.md` を読む。
- `AGENTS.md` の「Known regressions to avoid」は絶対に破らない。
  - `App/ProminentTabBar.swift` は `UISegmentedControl` のまま。SwiftUIの `Picker` に置き換えない。`allowsHitTesting(false)` を付けない。
  - ファイル画面のナビゲーションバーをスクロール量のフラグで出し入れしない。「ファイル／プロジェクト」のセグメントや新しく足す行は、List の中（先頭行）に置いてスクロールで流す。
  - ジャーナルの `ScrollView` を主スクロールビューのまま保つ（外側に別の ScrollView を重ねない）。
- デプロイターゲットは iOS 18、SDK は iOS 27。iOS 26/27 の API は `if #available` / `@available` で囲む。
- 1ファイル1型。`#Preview` / `PreviewProvider` は禁止。構造体の stored property は `var`。コメントは「なぜ」だけ書く。
- 記録は SQLite（`LocalStore` / `RecordStore`）に保存し、設定だけを `UserDefaults` / `@AppStorage` に置く。`@AppStorage` は View の中だけで使う。
- Codable に足すフィールドは `decodeIfPresent` で既定値を持たせ、既存データを読めなくしない。
- サンプルや架空の内容を生成しない。エンジンが動かないときは失敗として理由を表示する。AI処理は、利用者が明示的に実行したときだけ走らせる。
- UIの文言は日本語。省略記号は「…」を使い、`...` は使わない。アイコンは SF Symbols。アイコンだけのボタンにもアクセシビリティラベルを付ける。
- アニメーションは既存の `MemoraMotion` かスプリング（`.smooth` / `.snappy` / `.bouncy`）を使う。Reduce Motion のときはフェードだけにする。
- 1項目ごとにビルドを通し、`UX01: …` の形でコミットする。ビルドが通らない状態ではコミットしない。
- 全項目の完了後、`docs/IMPROVEMENT_BACKLOG.md` に「UXレビュー（2026-09）」の表を足す。各IDの状態は既存の4つ（未着手／実装済み・未検証／検証済み／保留）で記録する。
- 仕様が曖昧なときは既存の実装と `DESIGN.md` に合わせる。判断した内容はコミットメッセージとバックログのメモに残す。UIの変更に合わせて `DESIGN.md` の該当箇所も更新する。
- やらないこと: サインイン、課金、クラウド保管、MCP、CloudKit共有には触れない（未接続のまま）。

## P0 — 中核体験の欠落・誤解を招く挙動

### UX01 会議詳細の再生コントロールを戻す（ミニプレーヤー）

**現状**: `MeetingDetailView` にあるのは、ツールバー中央の再生/一時停止ボタンだけです。再生位置の表示、シーク、15秒戻し・送り、速度変更がなく、DESIGN.md の「Meeting detail」と B05 の仕様から後退しています。`AudioPlayerService` には `seek(to:)`・`skip(by:)`・`rate`・`currentTime`・`duration` が既にあります。

**実装**:
- 新規 `App/MeetingPlaybackBar.swift` を作る。`AudioPlayerService` を受け取り、次を並べる。
  - 1段目: 再生位置の `Slider`（ラベルは「再生位置」）。値は操作中だけローカルに持ち、指を離したときに `seek`。経過時間と残り時間を `monospacedDigit` で表示。
  - 2段目: 15秒戻し（`gobackward.15`）、再生/一時停止、15秒送り（`goforward.15`）、速度の `Picker(.menu)`（0.5 / 0.75 / 1 / 1.25 / 1.5 / 2倍）。
- 速度は `UserDefaults` の `memora.playbackRate` に保存し、`load` のときに適用する。
- 表示条件: 音声があり、その画面で一度でも再生したら表示し、画面を離れるまで残す。インライン編集中（`model.isInlineEditing`）とキーボード表示中は隠す。
- 配置: 画面下部。AI composer とタブバーの領域（`model.bottomContentClearance` の仕組み）と重ならないようにする。プレーヤーは機能レイヤーなので `memoraGlass` を使ってよい。
- 録音中は操作を無効にし、「録音中は再生できません」と表示する。
- ツールバー中央の再生ボタンは、バーを出す前の入口として残す。

**受け入れ条件**:
- 再生するとバーが現れ、スライダーでシークすると文字起こしのハイライトが追従する。
- 速度は再起動後も保持される。
- VoiceOver で全ボタンが読み上げられる。Reduce Motion では移動せずフェードする。

### UX02 話者名を詳細画面から一括で直せるようにする

**現状**:
- 詳細の文字起こしタブ（`MeetingTranscriptContent`）は `TranscriptSegmentText` に `onEditSpeaker` を渡しておらず、話者名を直せない。
- 話者を直せる `TranscriptView` は、AI回答の根拠からしか開けない。
- `MemoraModel.renameSpeaker` は1発言しか変えないため、「話者1→田中」を全行に反映するには行の数だけ操作が要る。

**実装**:
- `MemoraModel` に `renameSpeaker(meetingID:segmentID:name:appliesToAllSegments:)` を追加する（既存関数は置き換えてよい）。
  - `true` のときは、元の話者名と同じ全発言を置き換え、`speakerIsCertain = true` にする。
  - 検索キャッシュの無効化と保存は既存と同じ手順で行う。
- 話者編集シートを `App/SpeakerEditSheet.swift` に切り出し、`TranscriptView` と詳細の両方から使う。シートには次を置く。
  - 名前の入力。
  - 「この話者のすべての発言に変更」の `Toggle`（既定オン）。
  - 登録済みの人（`model.people`）の候補。人を選ぶと、その名前を使い、その人を会議の参加者に追加する（既存の参加者追加の処理を使う）。
- `MeetingTranscriptContent` から、`hasSpeakerSeparation` が真のときだけシートを開けるようにする。

**受け入れ条件**:
- 詳細の文字起こしで話者名をタップ →「田中」に一括変更 → 全行が変わり、参加者に田中が並ぶ。
- 話者分離がない文字起こしでは、話者名を押せる見た目にしない。

### UX03 Ask AI に渡す文脈を強くする（特に1ファイルへの質問）

**現状**（`App/MemoraModel+AI.swift`）:
- `context(for:tasks:)` が渡すのは、要約・決定（3件まで）・未決（3件まで）だけ。要約が空のときは最初の発言を400字。文字起こし本文は `bestExcerpt` の1行だけです。そのため、1ファイルが対象の質問（「〇〇さんは何と言っていた？」）にも答えられない。
- `questionWords` は日本語を2文字ずつに区切るため、「した」「です」「こと」のような機能語でも一致してしまい、順位付けがほぼ効かない。
- Ask AI の空状態は「会議をまたいで、意味から答えを探します」と説明しているが、実装はキーワード一致なので説明と合っていない。

**実装**:
- 送る文字数の上限を定数1か所にまとめる（例: 端末内の Foundation Models は約6,000字、クラウドBYOKは約40,000字）。`AIEngineService.effectiveEngine` の結果で切り替える。
- ファイル範囲（`AIQueryScope.file`、詳細の composer）の場合:
  - 上限内なら、文字起こし全文を `[mm:ss] 話者: 本文` の形で送る。
  - 上限を超える場合は、発言を約800字ずつのまとまりに束ねる。スコアの高いまとまりを時刻順に並べ、上限まで入れる。
- 全体・プロジェクト範囲の場合: 会議ごとに、タイトル・日付・要約・決定・未決・その会議のタスクと、スコアの高いまとまりを送る。会議は最大8件。
- スコアの付け方:
  - ひらがなだけの2文字は語として使わない。ストップワード（こと・です・ます・した・する・ある・いる・について・なに・どう など）も除く。
  - タイトルの一致は3倍、決定・未決・タスクの一致は2倍の重みにする。
- 根拠（`AIChatSource`）は、会議ごとに時刻つきの抜粋を最大3行持てるようにする（`excerpts: [Excerpt]`）。`AIMessageView` と関連画面で複数行を表示し、各行をタップするとその時刻から再生できる画面へ移る（既存の文字起こしへの遷移を使う）。
- 空状態の説明を「会議の要約・発言・タスクから、関係する部分を探して答えます。」に変える。
- `requestContent` は純関数のまま保つ。`SelfChecks.swift` に次の確認を追加する。
  - ファイル範囲で全文が入る。
  - 範囲外の会議が入らない。
  - 上限を超えたら切り詰められる。
  - ひらがなだけの2文字が語に含まれない。

**受け入れ条件**:
- 会議の詳細から「〇〇について誰が何と言った？」と聞くと、本文に基づいた回答と、時刻つきの根拠が出る。
- 範囲外の記録は送信内容に含まれない。

### UX04 サンプルデータを実データと区別し、すぐ消せるようにする

**現状**:
- 初回起動時は、ストアが空（`absent`）だと `SampleContent` の会議・プロジェクト・タスク・人・ライフログが必ず入る（`MemoraModel` の初期化にある `load(..., fallback:)`）。
- サンプルと実データの見分けがつかない。消す方法は設定の「プロトタイプ」の中にしかない。
- オンボーディングで「最初の会話を録音」を選んでも、サンプルが入る。

**実装**:
- `SampleContent` に判定用の関数（例: `isSample(meetingID:)`）を用意する。
  - 会議とプロジェクトは固定UUIDなので、そのまま判定する。
  - タスク・人・ライフログに固定UUIDがなければ固定UUIDを割り当てる（新規インストールから有効）。
  - 既存インストールで固定IDを持たない項目は、推測で判定しない。ただし、サンプル会議にひもづくタスクとライフログ（`meetingID` が一致するもの）は判定してよい。
- 初回起動（`absent`）では何も入れない。オンボーディングで「サンプルで見る」を押したときだけ、`model.loadSampleContent()` で入れる。「最初の会話を録音」と「スキップ」では空のまま始める。
- `MeetingCard`・`MeetingRow`・`LifeLogRow`・`ProjectFolderTile` に、小さな「サンプル」ラベル（Capsule、`.secondary`）を付ける。VoiceOver のラベルにも「サンプル」を含める。
- ファイルとジャーナルの一覧の先頭に、サンプルが1件でもある間だけ「サンプルを表示しています」の行と「サンプルを削除」ボタンを出す。ファイル画面では List の行として置き、スクロールで流す。
  - 削除は確認ダイアログを挟み、サンプル項目だけを完全に削除する（ゴミ箱には入れない）。実データには一切触れない。
- 最初の実録音、または最初の実インポートを保存した直後に一度だけ、サンプルが残っていれば「サンプルを削除しますか？」と提案する。提案したことは UserDefaults に記録する。
- 設定の既存の「サンプルを空に」も、同じ削除処理を呼ぶようにする。

**受け入れ条件**:
- 新規インストールで「最初の会話を録音」を選ぶと、ファイル・タスク・ジャーナルが空で始まる。
- 「サンプルで見る」を選ぶと、サンプルにラベルが付き、一括で消せる。消しても実データは残る。

### UX05 削除の取り消し（Undo トースト）

**現状**:
- ファイル一覧は、フルスワイプすると即座にゴミ箱へ移る。30日間は復元できるが、「最近削除した項目」は設定の奥にある。
- タスクの削除（`deleteTask`）は即時の完全削除。
- ノートの写真は、× を押すと確認なしで即座に削除される。

**実装**:
- 新規 `App/UndoToast.swift` と、モデル側の `pendingUndo`（新規型 `UndoAction`: 文言と取り消しの処理）を作る。
  - 表示は「〜を削除しました」と「取り消す」ボタン。5秒で自動的に消える。
  - 表示と同時に `AccessibilityNotification.Announcement` で読み上げる。
  - 位置はタブバーと composer の上。新しいトーストが出たら、前のトーストは確定扱いにする。
- 取り消しの対象:
  - 会議の削除（一覧のスワイプ、一括削除、詳細のメニュー）→ `restoreTrashedRecord` で戻す。
  - ライフログの削除 → `restoreTrashedLifeLogEntry` で戻す。
  - タスクの削除 → 削除前の値と位置をメモリに持ち、元へ戻す。
  - ノートの写真の削除 → 写真ファイルの削除はトーストが消えて確定するまで遅らせ、取り消したら元の位置に戻す。

**受け入れ条件**:
- 4種類の削除それぞれで「取り消す」を押すと、元の場所・順番に戻る。
- 取り消さなかった場合は、従来どおりゴミ箱に入る（タスクと写真は完全に削除される）。

## P1 — 毎日の操作の引っかかり

### UX06 「＋」を1つにまとめ、ジャーナルのツールバーを整理する

**決定済み（オーナー確認）**: 追加の入口は、タブバー右の「＋」（FAB）に一本化する。DESIGN.md の現在の方針（ジャーナル右上に＋を置く）より、この決定を優先する。

**現状**:
- タブバー右の「＋」（録音・音声インポート・オンライン会議・プロジェクト）と、ジャーナル右上の「＋」（メモ・写真・イベント・場所 = `LifeLogCreationSheet`）は、同じ記号なのに中身が違う。
- ジャーナルのツールバーは、メニュー・Omi・＋・歯車の4つで窮屈。
- Omi ボタンは、外部レコーダーを使わない人にも常に表示されている。

**実装**:
- `CaptureMenuPopover` を2つのグループに分け、間に区切り線を入れる。
  - 1つ目:「録音」「音声を読み込む」「オンライン会議」
  - 2つ目:「メモ・写真・場所を記録」（`LifeLogCreationSheet` を開く）「プロジェクトを作成」
- ジャーナル右上の「＋」を削除する。空状態の「記録を追加」ボタンは残す。
- Omi ボタンは、外部レコーダーを一度でもペアリングしたことがあるか、接続中のときだけ表示する（ペアリング履歴は UserDefaults に保存）。非表示のときも、サイドバーの外部レコーダー行から設定へ行ける。
- `ProminentTabBar` 本体には触れない（中身の `CaptureMenuPopover` だけを変える）。
- `DESIGN.md` を更新する。対象は C「ジャーナル」の「右上の＋から写真・録音・イベント・場所を手動追加」、C末尾の「＋」の説明、E「Navigation」の「＋」の役割。ライフログの追加も FAB から始まる、と書き換える。

**受け入れ条件**:
- どのタブの「＋」からでも、ライフログの記録を追加できる。
- ジャーナル右上に「＋」がない。

### UX07 ファイル一覧の密度・並び順・操作

**現状**:
- カードの最小の高さが190ptあり、1画面に2〜3件しか見えない。日付の区切りもない。
- 表示は既定で24件までで、残りは別画面（`AllMeetingsView`）にある。
- 並べ替えも、状態での絞り込みもない。
- 複数選択は左スワイプでしか始められず、長押しメニューもない。

**実装**:
- 日付ごとのセクション見出しを付ける（今日／昨日／今週／今月／それ以前は「2026年8月」の形）。見出しは List の中に置く。
- ツールバー右に `Menu`（`line.3.horizontal.decrease`）を置き、中に次を入れる。
  - 表示の切り替え: 「カード／リスト」の `Picker`。`@AppStorage("memora.files.layout")` に保存する。リスト表示は既存の `MeetingRow` を使った1行表示（タイトル・日時・長さ・状態）。
  - 並べ替え: 新しい順／古い順／長い順。
  - 絞り込み: すべて／要対応（文字起こし待ち・要約待ち・失敗・部分失敗）／処理中／完了。
  - 「選択」ボタン。
- 絞り込み中は、一覧の先頭行に解除できるチップを出す。
- 24件までの打ち切りをやめ、全件を表示する（List は遅延描画するため）。「すべての会話を一覧で見る」のリンクは削除する。`AllMeetingsView` を他から参照していなければ、ファイルごと削除する。
- カードと行に `.contextMenu` を付ける（開く・名前を変更・プロジェクトへ移動・共有・選択・削除）。削除は UX05 の Undo を使う。
- ナビゲーションバーの表示はスクロールで切り替えない（AGENTS.md の規則）。

**受け入れ条件**:
- リスト表示で1画面に8件以上見える。
- 並べ替え・絞り込み・表示形式は、再起動後も保持される。
- 長押しで操作できる。

### UX08 「要対応」の記録をまとめて処理する

**現状**: 読み込んだ音声は、文字起こしも要約も手動で始める設計（これは意図どおり）。ただ、待っている記録が一覧に埋もれ、気づきにくい。

**実装**:
- ファイル一覧の先頭行（セグメントの下）に、要対応が1件以上あるときだけ「文字起こし待ち n件・要約待ち m件」の行を出す。タップすると、UX07 の「要対応」の絞り込みを適用する。
- 同じ行に「すべて文字起こし」ボタンを置く。
  - 押すと確認ダイアログを出し、「n件の文字起こしを行います。クラウドの文字起こしを選んでいる場合は利用料が発生します」と、選択中のエンジンに合わせて明示する。
  - 実行は1件ずつ順番に `startTranscription` を呼ぶ。
  - 要約は一括では行わない（テンプレートの選択が必要なため）。
- 設定の「処理」セクションに「読み込んだ音声を自動で文字起こし」の `Toggle` を追加する（既定オフ、UserDefaults に保存）。

**受け入れ条件**:
- 要対応が0件のときは、行を出さない。
- 一括実行の途中でも、各記録の処理状態が一覧に正しく出る。

### UX09 タスク画面を「いつやるか」で整理し、期限を通知する

**現状**:
- 未完了／完了の切り替えと、期限順に並んだ平坦なリストしかない。
- スワイプ操作がない。
- 会議詳細の「次にすること」から、タスクの追加も編集もできない。
- 期限の通知がなく、完了日時も持っていない。

**実装**:
- 未完了タブをセクションに分ける: 期限切れ／今日／明日／今週／それ以降／期限なし。空のセクションは出さない。
- `MemoraTask` に `completedAt: Date?` を追加する（`decodeIfPresent`）。`toggleTask` で設定・解除する。完了タブは完了日時の新しい順に並べ、`nil` は末尾に置く。
- スワイプ操作: 先頭側は完了／未完了、末尾側は削除（UX05 の Undo）。
- 長押しの `contextMenu`: 編集・期限を「今日／明日／来週」に変える・元の会議を開く・削除。
- ツールバーに担当者の絞り込み `Menu` を置く（全員／担当なし／各担当者名）。
- `MeetingTasksSection`:
  - 行をタップすると `TaskEditView` を開く。
  - 末尾に「タスクを追加」を置く。`AddTaskView` に `meetingID` の初期値を受け取る引数を足す。
- 期限の通知: 新規 `App/TaskReminderScheduler.swift` を作る。
  - `AddTaskView` と `TaskEditView` に「期限に通知」の `Toggle` を置く。`MemoraTask.remindsAtDue: Bool` を追加する（`decodeIfPresent`、既定 `false`）。

## P0 レビュー指摘（UX01〜UX05 の修正）— RV01〜RV12

UX01〜UX05 の実装（52b6635〜9570957）をレビューした結果です。ビルドは通っています。以下は
コードを読んで確認した問題で、実行しての確認はしていません。RV01〜RV06 を先に直し、`RVnn: …` の形で1件ずつコミットしてください。

### RV01（高）再生バーが composer とホームインジケータに重なる可能性が高い
- **原因**: `MeetingDetailView` の `.safeAreaInset(edge: .bottom)` に置いている。タブの中身には、ルート（`RootTabView.bottomControls`）の safe area が伝わらない。だから各画面は `bottomContentClearance` を自分で足している。このままだと、バーはフローティングの composer と同じ位置に描かれる。また、Ask AI の composer にフォーカスしてキーボードが出ても、バーは隠れない（`isInlineEditing` しか見ていない）。
- **修正**:
  - バーは `RootTabView.bottomControls` の VStack に置き、composer の上に並べる。
  - モデルに `activePlayback: AudioPlayerService?`（`@ObservationIgnored` ではなく観測対象）を持たせる。詳細画面は「一度再生した」時点で登録し、`onDisappear` で自分のものだけを解除する。
  - 次のいずれかのときは隠す: `isComposing`、キーボード表示中、`isInlineEditing`。
- **受け入れ条件**: composer・タブバー・ホームインジケータ・キーボードのいずれとも重ならない。スクリーンショットで確認する。

### RV02（高）端末内AIの上限6,000字は、モデルのコンテキストに収まらない
- 端末内の Foundation Models のコンテキストは約4,096トークンで、これには指示文・履歴・回答が含まれる。日本語はおおむね1文字1トークン以上になる。6,000字を送ると、ある程度長い会議への質問はほぼ失敗する。（上限6,000字はこちらの指示書の誤りでした。）
- さらに、失敗の原因にかかわらず、すべて `.engineNotReady`（モデル未準備）として表示されてしまう（`AIEngineService.swift` の `catch`）。
- **修正**:
  - 端末内の上限は、文脈・履歴・添付をすべて合わせて約2,000字にする。SDKに `SystemLanguageModel` の `contextSize` / `tokenCount(for:)` がある場合は、`#available` で囲ってトークン数で判定する。
  - `LanguageModelError` のコンテキスト超過を `AIAnswerFailure` の新しいケース（例: `.contextTooLarge`）に分ける。超過したときは、上限を半分にして一度だけ再試行する。それでも失敗したら「記録が長すぎて端末内AIでは扱えません。範囲を絞るか、クラウドを選んでください」と表示する。
- **受け入れ条件**: SelfChecks で、端末内の上限を超える会議を与えたとき、送信する文字数が上限以下になる。超過エラーを「モデル未準備」と表示しない。

### RV03（高）添付と会話履歴が上限の計算に入っていない
- `characterLimit` は記録の部分にしか効いていない。添付（最大8,000字）と直近6往復の履歴は、上限とは別に上乗せされる。
- **修正**: `requestContent` を「全体の予算 → 質問 → 添付 → 履歴 → 記録」の順に配分する形にする。添付と履歴は、全体の予算の上限を超えないように切り詰め、切り詰めたことを回答に明記する。

### RV04（中）全体・プロジェクト範囲で、先頭の会議が大きいと何も送られない
- `libraryContext` は、ブロックが残りの予算を超えると `break` する。そのため、1位の会議の要約と抜粋が長いと、文脈も根拠も空になる。
- **修正**: 超えたブロックは残りの予算まで切り詰めて入れる。少なくとも1件は必ず送る。

### RV05（中）詳細から開いたAI回答で根拠をタップすると、元の詳細の状態が壊れる
- `AIQuestionView`（詳細から開くシート）で抜粋をタップすると、同じ会議の `MeetingDetailView` がシートの中にもう1つ積まれる。その `onDisappear` が `model.activeDetailMeetingID = nil` にするため、シートを閉じたあと、元の詳細で次のことが起きる。
  - composer の範囲が「全体」に戻る。
  - ジャーナル・タスク経由で開いている場合は、タブバーが再表示される。
  - 再生器が2つ同時に存在する。
- **修正**:
  - 根拠の会議が、いま開いている詳細と同じなら、シートを閉じて既存の再生器で `seek` と `play` を行い、文字起こしタブに切り替える（コールバックで渡す）。別の会議なら、従来どおり積む。
  - `activeDetailMeetingID` は単一の値ではなく、表示中の詳細のスタック（配列）にする。`onAppear` で積み、`onDisappear` で自分の分だけ取り除く。
- 同時に直すこと:
  - `initialPlaybackStart` は、音声がない場合も文字起こしタブに切り替え、該当する行までスクロールして強調する。
  - `onAppear` が再び呼ばれても、もう一度 seek しないように、一度だけ実行するフラグを持たせる。

### RV06（中）取り消すと、会議が一覧の先頭に戻る
- `restoreTrashedRecord` は `meetings.insert(…, at: 0)` で戻す。`meetings` は日付順に並べ替えていないため、古い会議を削除して取り消すと一覧の先頭に出る。一括削除の取り消しでは順番も逆になる。どちらも受け入れ条件「元の場所・順番」に反する。
- **修正**: 削除したときの位置を `TrashedRecord` に（`decodeIfPresent` で任意項目として）持たせ、その位置に戻す。位置がない古いデータは `createdAt` の降順になる位置に入れる。記録にひもづくタスクも同じように戻す。

### RV07（中）話者の編集で、キャンセルしても参加者が追加される
- `SpeakerEditSheet` は、人を選んだ時点で `toggleParticipant` を呼んでいる。
- **修正**: 選んだ人は `@State` に持っておき、「保存」を押したときに名前の変更と参加者の追加をまとめて行う。

### RV08（中）サンプル削除で、実データが参照している人も消える
- `deleteSampleContent` はサンプルの人（田中・佐藤）を無条件に削除する。そのため、利用者が実データの会議に付けた参加者や、タスクの担当者が、存在しない人を指すことになる。
- **修正**: サンプル以外の会議の `participantIDs` から参照されているサンプルの人は残す。確認ダイアログには「サンプルの会議に追加したタスクも削除されます」と明記する。

### RV09（中）最初の保存のあとのサンプル削除の提案が、表示されないまま終わる場合がある
- 録音を保存した直後は、録音シートを閉じている最中に `ContentView` の alert を出そうとする。そのとき表示が落ちることがある。それでも「提案済み」フラグは先に立つため、以後は二度と提案されない。
- **修正**: 提案は録音シートを閉じ終えてから（`completeCaptureDismissal` のあと）出す。「提案済み」は、利用者がどちらかのボタンを押した時点で記録する。

### RV10（中）写真の削除を確定する前にアプリが終了すると、ファイルが残り続ける
- 写真のファイル削除は、メモリ上のクロージャで5秒遅らせている。その間にアプリが終了すると、記録からは外れたのにファイルだけが残る。
- **修正**: 削除した時点で既存の `pendingMediaDeletions`（永続化済み）に登録する。取り消したら登録から外す。確定は、既存の削除待ち処理に任せる。

### RV11（低）アクセシビリティ
- **再生位置の Slider**: VoiceOver の増減操作では `onEditingChanged` が呼ばれず、`scrubValue` が変わるだけでシークしない。`isScrubbing == false` のときの `set` では、すぐに `seek` する。
- **Undo トースト**: VoiceOver・スイッチコントロールの使用中は、5秒では短すぎる。`UIAccessibility.isVoiceOverRunning` のときは10秒にする。

### RV12（低）細かい点
- ファイル範囲で質問の語が一致しなかったとき、冒頭の3行が「根拠」として表示される。この場合は根拠を出さない。
- `questionStopWords` に「ます」が重複している（動作に影響はない）。
- `questionWords` の `CharacterSet(charactersIn: "ぁ-ん…")` は、範囲ではなく文字の集合として解釈される（既存の問題。`alphanumerics` があるため動作はしている）。範囲にするなら `CharacterSet(charactersIn: "\u{3041}"..."\u{309F}")` などを使う。
