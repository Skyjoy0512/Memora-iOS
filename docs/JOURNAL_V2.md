# ジャーナル v2 — 実装指示と受け入れ条件（OpenCode向け）

`docs/UX_REVIEW_2026-09.md` の「0. 前提ルール」をそのまま適用する（AGENTS.md の既知の回帰、iOS 18ターゲット、1型1ファイル、`decodeIfPresent`、日本語文言など）。
J01〜J06 を順番に実装し、`J01: …` の形で1件ずつコミットする。UIを変えたら `DESIGN.md`（C「ジャーナル」、E「Navigation」、G「Life log」）も合わせて更新する。

## 目的

ジャーナルを「録音した記録の一覧」から「1日に起きたことのタイムライン」に広げる。
1日の流れ（移動・予定・会話・メモ）が1本の時間軸で読めて、そこから録音や会議の詳細へ移れるようにする。

- 自動で入るもの: 駅の通過と滞在（位置情報）、カレンダーの予定。
- どちらも**利用者がオンにしたときだけ**動く。既定はオフ。
- 取得したデータは**端末の外へ送らない**。

## オーナー決定事項

- タブの並びは **ファイル → ジャーナル → Ask AI → タスク** にする。
- 起動時に開くタブは、左端の**ファイル**にする。（ジャーナルを起動時のタブに残したい場合は、J01 の該当行だけを変える。）
- 選んだ日のタイムラインは**時刻の昇順（朝→夜）**に並べる。今日の場合は「いま」の位置に区切り線を入れる。検索結果は従来どおり新しい順。

## J01 タブの並びを入れ替える

**現状**: `RootTab` の case の順番（home, files, askAI, tasks）が、そのまま `ProminentTabBar` のセグメントの順番（`Item.allCases`）とサイドバーの順番になっている。`MemoraModel.selectedTab` の初期値は `.home`。

**実装**:
- `RootTab` の case を `files, home, askAI, tasks` の順に並べ替える。`rawValue` は変えない（バーの表示状態のIDなどに使われているため）。
- `RootTabView` の `TabView` の子の順番も同じにそろえる。
- `MemoraModel.selectedTab` の初期値を `.files` にする。
- `loadSampleContent()` が `selectedTab = .home` にしている箇所は、ファイルに合わせるか、サンプルを最もよく見られるタブにそろえる（判断した内容はコミットに書く）。
- `ProminentTabBar.swift` の実装には手を入れない（`UISegmentedControl` のまま）。

**受け入れ条件**:
- タブバー、サイドバーの一覧ともに、左（上）から ファイル・ジャーナル・Ask AI・タスク の順に並ぶ。
- 起動するとファイルが開く。
- タブを切り替えたとき、Liquid Glass の選択バブルは従来どおり、飛ばずにモーフィングして移動する。
- サイドバーは、ファイル・ジャーナルの両方で従来どおり開ける。

## J02 タイムラインの土台（表示用の項目と並べ方）

**実装**:
- 新規 `App/JournalTimelineItem.swift` を作る。
  - `enum JournalTimelineItem: Identifiable` に次の4ケースを持たせる。
    - `.entry(LifeLogEntry)`: 記録
    - `.calendarEvent(JournalCalendarEvent)`: 予定
    - `.movement(JournalMovement)`: 連続した駅の通過をひとまとめにしたもの
    - `.nowMarker`: 今日の「いま」の区切り線
  - `id` は、ケースごとに衝突しない文字列にする。
- 新規 `App/JournalTimelineBuilder.swift` を作る（純関数の `enum`）。
  - 入力: 選んだ日、その日の記録、予定、現在時刻。
  - 出力: 時刻の昇順に並べた `[JournalTimelineItem]`。
  - 規則:
    - 駅の通過（J03 の `origin == .stationPass`）が60分以内の間隔で続いたら、1つの `.movement` にまとめる。
    - 終日の予定は、配列には入れず、別の値として返す（J04 で日付の下に表示するため）。
    - 会議に録音が結びついた予定（J04 の照合）は、予定と記録の2行に分けず1行にする。
    - 今日のときだけ `.nowMarker` を入れる。
- `HomeView` は、この結果を描画するだけにする。`LazyVStack` と主スクロールビューはそのまま保つ（AGENTS.md の規則）。
- `SelfChecks.swift` に確認を追加する: まとめる規則、昇順、「いま」の位置、録音つき予定が1行になること、終日の予定が分かれること。

**受け入れ条件**:
- 手で追加したメモと録音の記録が、朝から夜の順に並ぶ。
- 今日を開くと「いま」の線があり、過去の日には出ない。
- 検索中は、従来どおり新しい順の結果一覧になる（タイムラインにはしない）。

## J03 位置情報から「〇〇駅を通過」「〇〇に滞在」を自動で記録する

**方針**: 電池への負担が小さい次の2つだけを使う。常時のGPS追跡はしない。
- **大幅な位置変化**（`startMonitoringSignificantLocationChanges`）: 駅の通過を検出する。
- **訪問の監視**（`startMonitoringVisits`）: 滞在を検出する。

どちらも「常に許可」の位置情報が必要で、アプリが終了していても、iOS がバックグラウンドでアプリを起動して知らせてくれる。

**データ**:
- `LifeLogEntry` に次の項目を追加する（すべて `decodeIfPresent`）。
  - `origin: LifeLogOrigin`（既定は `.manual`）。値は `manual` / `stationPass` / `visit` / `calendar`。`LifeLogOrigin` は String の raw 値を持つ enum にする。
  - `endDate: Date?`（滞在の終わり）
  - `latitude: Double?`、`longitude: Double?`（位置の丸めは次のサービスの項目を参照）
- `LifeLogSource` に `.automatic`（表示名「自動」）を追加する。

**サービス**: 新規 `App/AutoLocationLogger.swift` を作る（`CLLocationManagerDelegate`）。
- 起動時に `MemoraAppDelegate.application(_:didFinishLaunchingWithOptions:)` から作成・開始する。アプリがバックグラウンドで起動された場合もイベントを受け取るため、SwiftUI の View の寿命には依存させない。設定がオフなら何もしない。
- **駅の通過**:
  - 位置を受け取ったら、`MKLocalPointsOfInterestRequest(center:radius: 400)` と `pointOfInterestFilter = MKPointOfInterestFilter(including: [.publicTransport])` で近くの駅を探す。一番近い駅を「〇〇駅付近を通過」として記録する。
  - 精度（`horizontalAccuracy`）が1,000mを超える位置は捨てる。
  - 同じ駅は30分以内に重ねて記録しない。
  - 大幅な位置変化は精度が粗いため、文言は「付近」にする。
- **滞在**:
  - `CLVisit` の到着と出発がそろったら、「〇〇に滞在」（例: 9:10〜11:40）として記録する。名前は、既存の `LocationCaptureService.nearestPlaceName` と同じ手順（近くの駅 → 逆ジオコーディング）で求める。この関数は共有できる場所へ切り出す。
  - 滞在が10分未満なら記録しない。
- **除外する場所**:
  - 設定に「記録しない場所」の一覧を置く（UserDefaults に名前と座標を保存）。
  - 自宅・職場を除外したい場合を想定し、除外した場所の半径200m以内の出来事は記録しない。
  - 記録の詳細の削除メニューに「この場所を今後記録しない」を追加する。
- **保存の経路**:
  - バックグラウンドで起動されたときは `MemoraModel` が存在しない可能性がある。そのため、サービスは記録を LocalStore の受け箱のキー（`memoraAutoLifeLogInbox`）へ追記するだけにする。
  - モデルは、起動時と `scenePhase == .active` のたびに受け箱を取り込み（重複はIDで除外）、取り込みと受け箱の削除を1つのトランザクションで確定する。
  - ストアが保護中（`isStoreProtected`）の間は取り込まない。
- **座標**: 小数点以下3桁（約100m）に丸めて保存する。
- **設定**: 「ジャーナル」の節を新設し、次を置く。
  - 「移動と滞在を自動で記録」の Toggle（既定オフ）
  - 「記録しない場所」
  - 説明文: 「位置情報はこのiPhoneの中だけで使い、外部へ送信しません。電池への影響を抑えるため、駅の判定はおおよそです。」
- **許可の流れ**: Toggle をオンにしたら、まず「使用中のみ」を求め、続けて「常に」を求める。「常に」が得られなかった場合は Toggle をオフに戻し、理由と「設定を開く」を表示する。
- **Project.json**（`bitrig-standard-project` の規則に従う）:
  - `NSLocationAlwaysAndWhenInUseUsageDescription` を追加する: 「移動や滞在をジャーナルに自動で記録するために、アプリを使っていない間も位置情報を使用します。位置情報はこのiPhoneの外へ送信しません。」
  - `UIBackgroundModes` への `location` の追加は**不要**（大幅な位置変化と訪問の監視には要らないため。追加しない）。
- **DEBUG**: 計測画面に「現在地で駅判定を実行」ボタンを置き、移動しなくても一連の処理を確認できるようにする。

**表示**:
- `.movement` は1行で「渋谷駅 → 新宿駅 → 池袋駅」と時間の範囲を表示する。タップすると、各駅の時刻の一覧を開く。
- 滞在は、場所アイコンと時間の範囲を表示する。
- 自動で入った記録には、小さな「自動」の表示を付け、VoiceOver でも読み上げる。

**受け入れ条件**:
- 設定がオフの間は、位置情報の許可を求めず、監視も始めない。
- オンにして「常に」を許可すると、シミュレータの位置シミュレーション（City Run / Freeway Drive）または DEBUG ボタンで、「〇〇駅付近を通過」がタイムラインに現れる。
- 同じ駅が30分以内に重複しない。60分以内に続いた通過は、1行の「移動」にまとまる。
- 除外した場所の周辺では記録されない。
- アプリを終了した状態で移動しても（実機）、次に開いたとき記録が取り込まれている。
- 自動の記録は通常の記録と同じように削除でき、取り消し（UX05）と「最近削除した項目」が効く。
- オフにすると監視を止める。すでにある記録は消さない。
- 実機でしか確かめられない項目は「実装済み・未検証」と記録する。

## J04 カレンダーの予定をタイムラインに表示する

**方針**: 予定の元データは常にカレンダーにある。そのため、**Memora には保存せず、表示のたびに EventKit から読む**（二重に管理しない）。

**実装**:
- `CalendarService` に `events(on day: Date, calendars: [String]?) -> [JournalCalendarEvent]` を追加する。
  - `JournalCalendarEvent` は新規ファイルにし、次の項目を持たせる: `id`（eventIdentifier と開始時刻の組み合わせ。繰り返しの予定で回ごとに区別するため）、`title`、`start`、`end`、`isAllDay`、`calendarTitle`、`calendarColor`（CGColor から変換）、`location`。
- `HomeView` は、選んだ日が変わったとき、`EKEventStoreChanged` を受けたとき、`scenePhase == .active` になったときに読み直す。読み込みはメインスレッドを塞がない。
- **表示**:
  - 時刻のある予定: 時刻の範囲、タイトル、カレンダーの色の点（色だけに頼らず、カレンダー名を VoiceOver で読み上げる）を1行で表示する。
  - 終日の予定: 日付の見出しの下に、横並びのチップで表示する。
- **録音との結びつけ**:
  - `Meeting.calendarEventID` が一致し、かつ会議の `createdAt` がその予定の開始の前後12時間以内なら、その予定は「録音あり」として1行にまとめる（J02）。
  - その行をタップすると、会議の詳細を開く。
- **予定の詳細シート**（新規 `App/CalendarEventSheet.swift`）:
  - タイトル、時刻、場所、カレンダー名を表示する。
  - 開始の15分前から終了までの間は「録音を開始」ボタンを出す（既存の `startCapture(event:)` を使う）。
  - 「カレンダーで開く」（`calshow:` と開始時刻の URL）を置く。
- **設定**（「ジャーナル」の節）:
  - 「カレンダーの予定を表示」の Toggle（既定オフ）。オンにしたときに初めて、既存の `CalendarService.requestAccess()` で許可を求める。
  - 表示するカレンダーの選択（`EKCalendar.calendarIdentifier` を UserDefaults に保存。未選択なら全部を表示）。
- `NSCalendarsFullAccessUsageDescription` の文言を、ジャーナルでの表示も含むものに更新する: 「予定をジャーナルに表示し、会議の録音をすぐ始められるようにカレンダーを使用します。」
- カレンダーの日付セルの点は、従来どおり「記録がある日」だけに付ける（予定では点を付けない）。
- 検索は、保存している記録だけを対象にする（予定は検索しない。空の結果の説明にもそう書く）。

**受け入れ条件**:
- 設定がオフの間は、カレンダーの許可を求めない。
- オンにすると、選んだ日の予定が時刻順に並び、終日の予定は見出しの下に出る。
- カレンダーアプリで予定を追加・変更すると、ジャーナルに戻ったときに反映されている。
- 予定から録音した会議は、予定と記録の2行ではなく1行で表示され、タップで詳細が開く。
- 繰り返しの予定の別の回が、「録音あり」にならない。
- 許可が拒否されている場合は、設定に理由と「設定を開く」を表示する。ジャーナルには何も出さない（エラーの行も出さない）。

## J05 タイムラインの表示を整える

- 各行の左端に、時刻（開始時刻、または開始〜終了）を `monospacedDigit` で表示する。種類のアイコンは、既存の `LifeLogKind` の symbol と、予定・移動・滞在のアイコンを使う。
- 行の見た目は、既存の `LifeLogRow` の余白・書体と統一する。予定・移動・滞在の行は新規の View にし、1ファイル1型を守る。
- 「いま」の線は、細い線と「いま」のラベルにする。色は `.primary`（DESIGN の配色規則に従い、赤は録音専用のままにする）。
- 空の日の表示は既存のカードを使う。ただし、予定だけがある日は空とはみなさない。
- 今日を開いたときに「いま」の位置まで自動でスクロールするかどうかは任意。行う場合は、最初の表示のときだけにする。

**受け入れ条件**:
- VoiceOver で、各行が「時刻・種類・タイトル」の1要素として読み上げられる。
- 文字サイズを最大にしても、時刻とタイトルが切れずに折り返す。
- Reduce Motion で移動のアニメーションが出ない。

## 2026-10-18 — フラットなタイムラインと週カレンダー

ジャーナルのイベントアイコンと週カレンダーからLiquid Glassを外した。タイムラインの
アイコンは淡いニュートラル色の円形にし、影・輪郭・ガラスは使わない。時刻・アイコン・
カードの位置を揃え、つなぐ縦線は1.5ptの控えめなグレーにした。記録の間と末尾には
同じフラットな円形の＋を置き、44pt以上のタップ領域から記録を追加できる。

週カレンダーは`GlassEffectContainer`と選択カプセルのモーフィングをやめ、選択日だけを
淡いグレーの角丸背景で示す。今日は文字のウェイトと色で区別し、記録のある日のドット、
横スクロール、選択日のセンタリング、日付による絞り込みはそのまま維持する。
Light/Dark、Dynamic Type、VoiceOver、Reduce Motionに対応する。

タブバー・＋ボタン・composer・ナビゲーションバーなど、他のLiquid Glassは変更しない。
`memoraGlass`と`MemoraGlassContainer`の共通実装も維持する。
