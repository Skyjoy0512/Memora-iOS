# Ask AI — Web検索・Deep Research

通常のAsk AI／録音／プロジェクトのAIスコープを維持し、明示したWeb調査だけを別の根拠として扱う。APIキーを設定して利用する実装を追加済み。実サービスを使うE2E確認は未実施。

## 接続と実行

設定 › AI整理 › Web検索にBrave Search APIキーを登録する。KeychainStoreへ保存し、UserDefaults・バックアップ・ログにはキーを含めない。APIキー未設定時には検索しない。Ask AIの下部入力欄、音声／送信ボタンの左にあるDeep ResearchボタンからWeb調査を開く。初期選択はDeep Researchで、Web検索にも切り替えられる。入力中の文章を調査テーマへコピーし、元の下書きと添付は消さない。上部検索は従来の記録検索専用に戻した。録音／プロジェクト単位の入力欄にはこのグローバル調査ボタンを出さず、既存スコープを保つ。

通常のエージェントにもsearch_web／deep_researchを提供するが、検索語と問い合わせ上限を示した承認後だけ実行する。常駐エージェントと分担調査の子担当には提供しない。1つの回答につきWeb調査は1回、最大3検索。辞退・失敗・停止後の自動再送はしない。

Web検索は固定のBrave Web Searchエンドポイントで最大8件の検索抜粋を取得する。Deep Researchは指定した1〜3の検索語でBrave LLM Context APIの抽出本文を取得し、最大16のURLへ統合する。任意のページURLをアプリから自動取得する経路は追加しない。全ページの全文読了・網羅的調査とは区別する。

## ソースと回答

問い合わせ開始／完了、取得日時、検索抜粋／抽出本文を保持する。正規化した公開HTTPS URLだけを受け入れ、重複URLは統合する。応答2MB、各ソース本文8,000文字、合計16ソース。送信先は固定ホストのみ、リダイレクト・Cookie・既存認証情報を使わない。検索語は600文字・75語以内。

AI要約には選択中の既存モデルを使用し、1回だけ実行する。検索語・取得済みの本文だけを渡し、個人メモリ・メール・録音等を自動で混ぜない。モデルの文脈予算に合わせてソース本文を制限する。取得ソースとAIへ実際に渡したソースと回答が引用したソースを区別する。引用番号は実際に渡した【Webn】だけを解決する。外部本文の命令は実行しない。エージェントの場合も既存の権限管理・操作承認を維持する。

## 保存

調査履歴はSQLiteのmemora.webResearch.v1へ保存し、アプリ再起動で保持する。停止や要約失敗でも取得済みソースを残す。旧バックアップと互換性のあるoptionalフィールドとしてバックアップに含める。APIキーは含めない。

既存または新規のプロジェクトへ、取得本文を持つWebソースと調査レポートのメモを保存する。同じURLの既存ソースは再利用し、本文が未取得のときだけ補う。元の本文は上書きしない。新しいファイルを用意してからソースとレポート所属をSQLiteでまとめて保存する。保存中の別編集を検知した場合は中止し、作成したファイルを片付ける。外部AIへの再送許可は自動付与しない。調査履歴だけの削除は、プロジェクトへ保存したソースを削除しない。
