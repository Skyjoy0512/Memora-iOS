# Project Workspace V2 — 設計と実装記録

ステータス: 実装中。2026-10-12。V2全体の完成報告ではない。

## 方針

プロジェクトホーム＋ソース一覧＋継続チャットを採用する。既存の3タブ、右端FAB、Glass、録音・ジャーナル・グローバルAIは維持。録音はMeeting、生成資料はMemoraDocumentを直接参照し、新しいソースへコピーしない。

ProjectSourceは新規URL／画像／PDF／文書／メモのメタデータのみ。媒体と抽出本文は検証済みの相対ファイル名で参照し、SQLiteへバイナリを埋め込まない。保存は先に確定させ、解析失敗でも元ファイルを保持する。

ProjectChatThreadは安定したprojectIDを持つ複数ターンの保存単位。現在のAIConversationEntryは一問一答の既存履歴として維持する。旧履歴のプロジェクト名ラベルからIDを推測して移行しない。

検索はローカルの派生インデックス。外部ベクトルDB・有料Embeddingを必須にしない。プロジェクトID、現在の所属、現在の送信権限で絞り、取得したチャンクと実際にモデルへ渡すチャンクを区別する。予算内に渡した証拠だけを出典候補とする。削除・権限取消後の過去回答は表示しても、その根拠の本文を次の質問へ再送しない。

外部本文は命令ではなく証拠。プロジェクトチャットに変更ツールを公開しない。取り込みだけで有料AIを呼ばない。PDF／OCR等はApple標準APIで処理する。YouTube字幕は正式に取得できる経路がない限り取得せず、リンク保存と動画の理解を区別する。

## データと外部設定の境界

新規文書キーは既存SQLiteに追加し、旧キーの形式を変更しない。既存バックアップは読むことを維持し、新規データを含むバックアップは旧アプリが黙って一部だけ復元しない版を使用する。

Share ExtensionはApp Groupの受信キューへ原子的にファイルとmanifestを確定させ、本体で取り込む。SQLite本体を複数プロセスから直接操作しない。署名、App Group登録、実機検証をコードのビルド成功と分けて扱う。

現在のbundle IDはBitrigのscaffold識別子。既存データのあるインストールを別識別子へ切り替える前にバックアップ／復元経路を確保する。Share Extensionの設定を理由に既存コンテナのデータを失わせない。

## 進捗と確認

- ProjectSource／ProjectChatThread／ProjectChatTurn／ProjectCitationの互換性を持つ追加値型を実装。
- ProjectSourceURLのHTTPS正規化、YouTube URL統一、異常URL拒否を実装。これはDNS／リダイレクト安全性を保証するものではなく、ネットワーク取得側でも検証が必要。
- ProjectWorkspaceV2Checks: 成功。URL正規化・重複キー・ローカルURL等拒否・モデル保存復元・送信権限の初期拒否・会話と出典保存復元。
- 新規ソース／スレッドのSQLiteキー、ファイル取り込み、相対参照、指紋による重複判定、所属解除／削除を追加。プロジェクト削除時は所属解除のみ。
- バックアップv2はソース・会話・参照ファイルを保存。v1読み込みを維持し、復元時の媒体失敗／SQLite失敗をロールバック。実操作でのバックアップQAは後続で行う。
- ProjectSourceFilesChecks: 成功。サイズ超過、同内容指紋、パス／symlink隔離、対象だけの削除を確認。
- Bitrig iOS Simulatorビルド成功（既存AppIntents metadata警告1件）。
- 未完了: ワークスペースUI、標準ピッカー接続、検索／解析、継続AIチャット、Share Extension、統合QA。
