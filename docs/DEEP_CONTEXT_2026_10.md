## 実装したこと

### 1. モデル別のコンテキスト予算（P0-C）

- `App/ModelCapabilities.swift`
  - モデルごとにコンテキスト窓、最大出力、ツール/推論/構造化出力/画像、料金、
    プロンプトキャッシュ、最大リクエストサイズ、取得元、最終確認日時を持つ。
  - 完全一致のIDだけをカタログから引き、似た名前のモデルへ能力を流用しない。
  - 独自エンドポイント・未登録モデルは保守的プロファイル（32,768 tokens / 8,192 出力 /
    512 KiB）へ落とす。
  - 利用者がモデルごとに上限を上書きできる（`ModelCapabilityOverride`、UserDefaults）。
  - 料金は確認できるまで `nil`。推定費用を捏造しない。
- `App/TokenBudgetManager.swift`
  - `chat / agent / deepAnalysis / presentation / research` の目標を、実際の窓から
    出力予約と安全余白を引いて決める。固定40,000文字は廃止。
  - 日本語は1文字≒1トークンとして安全側に見積もる。英字は約3文字/トークン。
  - 深い依頼（PowerPoint・経営報告・事業計画・経緯・Deep Researchなど）を
    `DeepContextPolicy` で判定し、通常質問と分ける。
- `AIEngineService.contextCharacterLimit` は選択モデルと用途を受け取る。
- `AgentSessionBudget` / `AgentOutputBudget` / `AgentRunBudget` はモデルに応じた
  有限の上限を持つ。無制限のリクエスト・ループ・出力は許可しない。
- `CloudAgentSession` は `max_tokens` と出力予約をモデルの上限内に収める。
- 添付は解析60,000文字まで保持し、モデルごとの予算で送信量を決める。
- `MemoraModel+Agent` の初期検索・個人記憶・スキル手順の予算を動的にした。
- 設定 › AIと要約 › モデルの上限 から、選択モデルの実際の値と取得元を確認し、
  独自エンドポイント用に調整できる。

### 2. 資料の根拠パックと背景理解（P0-B）

- `App/PresentationEvidencePack.swift`
  - 目的・読者・判断事項、プロジェクト、時系列、意思決定、関係者、事実、数値、
    矛盾、リスク、未確認、前回最終版、出典、権限、版を持つ。
  - 各事実は原資料ID・日時・引用位置・事実/意見/仮説・確信度を保持する。
  - 参照不可の記録は本文へ入れない。許可未確認の記録もクラウド資料では使わない。
  - 決定は主題ごとに新しい有効決定を採用し、撤回・中止された決定を現行として扱わない。
    履歴は残す。
  - 同じ語を含み数値が異なる抜粋を「矛盾」として明示し、どちらが正しいかは断定しない。
- `App/MemoraModel+PresentationContext.swift`
  - 現在のワークスペースから会議・要約・決定・未決・タスク・資料・人物名・長期メモリ・
    ジャーナルを横断して候補を作る。人物の非公開メモは送らない。
  - 前回の最終提出版（artifactを持つスライド資料）を優先して土台にする。草稿は最終版と
    呼ばない。
- `MemoraModel+Agent` は深い依頼のとき、検索結果より先に根拠パックを渡す。
  読んだ記録は既存のクラウド読取記録へ登録する。
- PowerPointスキルの手順に、根拠パックの時系列・決定・矛盾・未確認の確認、
  最終提出版の再利用、撤回済み決定の除外、Jinba規約の優先を明記した。

## 追記: 二段階検索と調査範囲の記録

- 検索を2段階にした。1回目は依頼語で候補を採点し、上位記録に繰り返し現れる語
  （依頼語にない語）を2回目の検索語へ展開する。全記録の2割超に現れる語と
  数字だけの語は展開語から外し、雑音で全件が当たるのを防ぐ。
- 依頼語自体も、許可済み資料の2割超に現れる語（例「会議」）は重みから外す。
- `Investigation`（候補数・許可数・採用数・検索語・展開語・2回目実行・打ち切り）と
  `gaps`（決定・数値・前回最終版の不足、予算超過）を根拠パックへ追加。
- 1回の構築で見る許可済み資料は2,000件まで。超過は打ち切りとして記録する。
- `tools/checks/PresentationDeepContextChecks.swift`: 129資料、複数年、商品名が同じ
  記録、語の異なる重要記録、取消済み・未判定、同姓同名、数値矛盾、最終版、
  決定の交代・撤回、提案シナリオの不足検出、予算内・5秒以内を検査。
- GitHub Actions は予算上限のため `workflow_dispatch` のみ。ローカル検査は継続する。
