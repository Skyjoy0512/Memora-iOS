# 長時間音声の再生予約

2026-11-02。UI・保存形式・録音原本を変えず、既存のAVAudioEngine再生を改修した。

従来は残り全フレームをUInt32へ一括変換していた。24時間・96kHzは8,294,400,000
フレームとなり、UInt32の上限を超える。AudioPlaybackScheduleはInt64の原本位置を保ち、
通常60秒ずつ、最大2区間だけ予約する。再生完了通知から次の区間を補充するため、
録音全体をPCMへ読み込む処理や、長さに比例する予約配列は追加しない。

停止・一時停止・シーク・再生開始失敗で予約の世代を失効する。前のファイルの通知や
同じ区間の重複通知は次の予約を作らない。再開位置とプレイヤーのサンプル時計の関係は
従来どおりで、区間補充によって原本の時間をリセットしない。シーク入力のNaN・無限大・
整数範囲外も変換前に処理する。停止直後に新しい再生が始まった場合、キャンセル済みの
位置更新Taskが新しい再生状態を書き換えないよう、sleep後にも取消を確認する。

## 実施した検査

`python3 -B tools/checks/run-audio-playback-checks.py`

- productionの予約型をSwift 6でコンパイル。8/44.1/48/96/192kHzの24時間を各1,440区間で
  計画し、全フレームの連続性・重複なし・予約数最大2を確認。
- 中途開始、終端、極端なサンプリングレート、Int64上限付近、NaN/無限大を確認。
- productionのenqueueメソッドをそのまま抽出して、実AVAudioFileのメタデータと
  コールバックfixtureで補充・末尾・重複通知・再開後の古い通知・取消・一時停止を確認。
- productionのtickerを抽出し、sleep中に取消してすぐ再開するraceを確認。
- iOS previewのビルドと起動要求は成功。既存の非推奨API等の警告11件は残る。

これらは実際の出音、24時間の実ファイル、OS割り込み、バックグラウンド連続動作、
メモリ使用量・電池・RTFの実測を意味しない。音声出力と完了通知のタイミングはfixture。

## 次の検証と実装

実機で60秒境界の連続性、速度変更、一時停止/再開、末尾、引用時刻へのジャンプ、
ロック画面操作、他の録音によるセッション取得、画面を閉じて別音声を開く操作を確認する。
バックグラウンドで補充Taskが遅延すると再生待ちが生じ得るため、無音が発生しないとの
保証は実機検証後に判断する。

録音のファイルローテーションと複数原本の管理は未接続。現在の録音・再生・削除・
バックアップは単一のaudioURLを使う。分割ファイルを先に有効にせず、原本参照、
復旧、統合時刻、削除のundo、バックアップ/復元を合わせて実装する。
資料取り込みの50MB/6時間制限もこの再生改修では変更していない。
