# タスクとレコーダーの改善（2026-10-10）

## 個人のタスク

- タスクタブは自分の担当だけを表示する。明示した「自分のタスク」が最優先で、未指定の旧記録はプロフィール・アカウント名、Me・自分・私・わたしとの完全一致で判定する。
- 会議に紐づく担当未確認の課題は自分の担当と推測しない。元の会議から編集して「自分のタスク」をオンにできる。旧記録の会議に紐づかない担当なしの手動課題は個人の課題として扱う。
- 課題は削除・再分類せず、表示だけを絞る。他の人の課題は元の会議・人物画面に残る。
- 手動追加は自分の課題が既定。他の担当を記録するときは「自分のタスク」をオフにする。

## 課題の階層・メモ・資料

- `TaskRelationships` に親課題とMemoraの資料IDを保存する。子・孫課題は同じタスク型で扱い、循環した親子関係は保存しない。
- 編集画面から子課題を追加・編集でき、その子からさらに孫課題を追加できる。子が残る親課題の削除は拒否し、子を先に移動・削除するよう説明する。
- メモ・完了条件は既存の `detail` に保存する。資料は `MemoraDocument` への参照で、資料本体を課題にコピーしない。添付の選択は課題の保存時に確定する。
- 削除した資料の参照は「削除された資料」と表示する。任意のPDFや画像を課題へ取り込むファイル添付、チームの資料・課題添付の同期はこの段階では実装していない。
- 新しい任意フィールドはSQLiteのタスクの中に保存する。既存のバックアップにも含まれ、旧タスクは追加フィールドなしで読み込める。

## チームボード

- チームプランでは表示を「自分のタスク／チームボード」に切り替えられる。ボードの列は着手前・進行中・相手待ち・完了で、担当と自分のみの絞り込みがある。
- `TeamBackend.taskBoard` が返すチームID・リビジョン・タスク・本人の課題IDだけを表示する。個人のSQLiteタスクはボードの代わりに使わない。
- 状態変更は `updateTask` に現在のリビジョンを渡し、サーバーが返した同期結果で表示を更新する。競合の検出・認証・本人判定・権限確認は接続先サーバー側で行う契約とする。別ワークスペースの応答や重複ID・循環を含む応答は拒否する。
- 現在は `UnconfiguredTeamBackend` のままで、本番の同期サービスは未接続。実際のチームの一覧・認証・更新・複数端末の同期は動作しない。未接続の理由を表示し、共有できたとは報告しない。
- チーム課題の追加・階層編集・メモ編集・資料添付のクラウド更新は別段階。ボードの状態変更にも本番バックエンドの接続・実機検証が必要。

## レコーダー・メニュー

- サイドメニューの重複したタブ項目を除去し、ライブラリ・プロジェクト・接続と設定を残す。
- 外部レコーダーを押すと、未登録ならOmiのペアリング、登録済みならデバイス詳細を開く。未接続のデバイスを接続済みとは表示しない。再接続と確認付きペアリング解除を用意する。
- ファームウェアのバージョンは実機から読めたものだけを表示する。更新処理は未実装で、更新ボタンからその理由を説明する。未検証のファームウェアをBluetooth経由で書き込まない。
- コンテンツのアイコンは背景タイルより小さく描画し、SFと非SFで同じ図柄サイズにする。ファイルカードの日付からカレンダーアイコンを除く。
- ドロワーでは前面の画面幅を固定し、描画上の変換で移動する。ナビゲーションタイトルの左余白を維持する。

## 検証

- 所有者判定、子・孫の順序、循環拒否、旧タスクの互換性、資料参照の往復、チーム応答の重複拒否、ボードの状態変更をDEBUG自己チェックに追加。
- `bitrig build -destination selected` が成功。既存の警告5件は残っている。シミュレーターの「計測と自己チェック」で `Task ownership and hierarchy` と `Task and journal compatibility` の成功を確認した（正式なテストターゲットの代わりではない）。
- シミュレーターでMeの未完了2件だけの表示、子課題フォーム、資料選択と編集画面への反映、外部レコーダーから直接ペアリング画面を開く動作、ドロワー表示中のジャーナルの左余白を確認した。確認用の課題や添付は保存せず、既存記録を変更していない。
- Bluetooth実機の接続・解除・ファームウェア取得、同期サーバー、複数端末の競合、任意ファイル添付は未検証または未実装。
