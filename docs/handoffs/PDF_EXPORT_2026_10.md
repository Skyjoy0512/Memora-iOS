# 資料PDFの改ページ・応答性の改善 — 2026-10-30

前回の[UI/UX検証](UI_UX_IMPLEMENTATION_2026_10.md)で残った、資料PDFの任意位置での分割と、同期書き出しによる操作待ちを改善した。対象は資料詳細の「PDFで共有」。既存の資料・スライド・SQLite・原本ファイルの保存形式、録音・文字起こし、会社テンプレートの対応範囲、Project.jsonは変更していない。

## 変更後の挙動

- **本文の改ページ**: 全体を縦長に描いて切る方式を廃止し、Core Textで文字の行を組む。1ページに収まる段落はまとめ、長い段落・コード・引用は完成した行の境界で続ける。見出しと後続の内容もまとめて配置する。
- **表**: 4列以下はA4幅に収まる表として描画。通常の行はまとめ、ページを超えるセルは完全な行で分割する。続きでは列見出しと短い行識別子を繰り返す。5列以上はラベル付きの縦の一覧に展開し、値を省略しない。極端に長い列見出しも切り捨てず本文として配置する。
- **文字と体裁**: ベクター文字を維持し、日本語の検索・選択、太字・斜体・コード、引用の罫線、箇条書き、チェックボックス、取り消し線、明示されたリンク先を保持する。各ページに番号を付ける。端末の文字サイズ・ダークモードは印刷結果を変更しない。
- **進行と取消**: 本文の組版・描画・ファイル生成はメインアクター外で実行する。組版中は不定の進行表示、描画中は実際のページ数による進捗を表示する。キャンセルや画面からの離脱で作業を取り消し、失敗・取消時は生成途中のファイルを削除する。
- **古い処理の反映防止**: 処理ID、資料のスナップショット、ワークスペースと世代、復元・保護状態を照合してから共有へ渡す。取消・再試行後に届く進捗や結果を新しい処理へ反映しない。順序が入れ替わった進捗通知で表示を後退させない。
- **ファイル保護**: 一時ファイルへ書き、PDFとしてのページ数を確認してから完成ファイルへ移す。既存の出力先・既存の途中ファイルを上書きしない。取消後に遅れて成功したファイルも破棄する。保存済みの原本は削除しない。
- **スライド**: 既存の共通SlidePageLayoutとSlideViewを維持し、組版を作業タスクへ、SwiftUIの描画をページごとに譲る処理へ変更した。会社ファイルの原本を含むPDF変換は引き続き未対応と明示する。

主な実装は `DocumentPDFLayout` / `DocumentPDFRenderer` / `DocumentPDFFile` / `DocumentPDFExportSession` / `DocumentPDFExportProgressView`。資料詳細から使用する。Debugの状態と復旧ギャラリーには、保存・外部通信しない架空データの検証導線を追加した。

## 検査

`python3 tools/checks/run-document-pdf-checks.py` で本番の組版・描画コードを実行する。

- 日本語の長文、結合文字・絵文字、72行の表、ページを超えるセル、幅の広い表、コード、引用・箇条書き・チェックボックス、リンク、取り消し線、末尾の文字を含む架空の資料をPDF化。
- 最終fixtureは13ページのA4。全行・罫線のページ内配置、通常の表行の維持、繰り返し見出し、検索可能な日本語と末尾、ページ番号、PDFのリンク注釈を検査。見出しと最初の表行について、前段の長さを変えた25条件を検査した。
- 描画中の取消で完成・途中ファイルの両方が残らないこと、書き込み不能時に成功を返さないこと、既存のファイル内容を保持することを確認。
- 本番の進行管理を、応答を保留できるwriterのfixtureで実行。取消→即再試行、古い成功・進捗、順序違いの通知、資料・ワークスペース失効、失敗通知、取消後に共有しないことを確認。
- 生成した全ページの一覧と、先頭・表・長いセル・最終ページの拡大画像を目視確認した。Popplerへの依存は追加せず、PDFKitで独立に読み戻して描画・文字抽出している。

`bash tools/checks/run-slide-checks.sh` も通過。9ケース・59派生ページの文字の順序、書式・幾何、ノート、旧形式、実PPTXの独立ZIP/XML検査を確認した。Officeの最終描画検査ではない。
