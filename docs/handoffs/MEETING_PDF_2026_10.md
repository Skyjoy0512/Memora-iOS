# 会議PDFの改ページ・取消 — 2026-10-31

対象は会議詳細の「その他 → PDFで共有」。縦長の画面画像を固定高さで切っていた出力を、資料PDFのCore Text組版へ移行した。

## 挙動

- 日本語を検索・選択できる文字として出力し、段落・表の行・長いセル・見出しの改ページを共通化。巨大な1枚の画面画像は生成しない。
- 会議名、日時、時間、録音元、要約、決定事項、次の行動、未決事項、重要ポイントという従来の印刷内容を保つ。対象会議のタスクだけを元の順で載せ、担当者がある場合は併記する。文字起こし・音声・写真・ノートの追加掲載は行っていない。
- 準備中は不定進捗、描画中は実ページ数を表示する。資料PDFと共通の取消操作を使い、workerへ取消を伝える。準備完了後にも取消を確認し、完了直前の取消でも共有しない。
- 共通の出力セッションを使用し、取消直後の再試行、古い進捗/完了、記録・対象タスク・workspace世代・復元・保護状態の変化を判定する。画面を離れたら取消。古い結果は破棄し、再試行の状態を上書きしない。
- 部分ファイルへの描画・検証後に完成ファイルへ移す。失敗・取消では自分の部分/完成ファイルを削除する。共有終了時の削除も既存の一時ファイル用ガードを通す。
- 記録の保存形式、SQLite、録音・文字起こし、会社テンプレート、Project.jsonには変更なし。

## 自動検査

`python3 tools/checks/run-document-pdf-checks.py` は以下をすべて通過。

- 既存の13ページの本文PDF検査: 文字/絵文字、改ページ境界、表の継続、最終行、フッター、URLリンク、取消と保存失敗の後始末。
- 本番の共通出力セッション: 取消/再試行、古い進捗/完了、変更された入力、失敗表示、取消後に共有しないこと。
- 会議用の本番wrapper・内容組立・描画器: 5ページの実PDFをPDFKitで読み戻し、全セクション、最終表行、数値、録音元/時間、タスクの会議IDによる除外/順序/担当者、空のセクションと平文を確認。
- 会議wrapperの実workerが描画開始してから取消。戻り値がCancellationErrorとなり、自分の完成ファイルとpartialファイルが残らないことを確認。

会議wrapperのホスト検査ではMeeting/MemoraTaskを最小のテスト用snapshotに置き換える。アプリの実型との結合はBitrigのiOSビルドで確認する。共通描画器のページ境界検査は本番コードをそのままコンパイルしている。ホストの成功を実機の性能や外部共有先の成功とは扱わない。

## iOS操作の確認

iPhone 18 Pro MaxのBitrigプレビューで以下を確認。

1. Debugの架空データで会議PDFを生成。実表示728 / 1,430ページの処理中にキャンセルし、操作可能な検証画面へ戻った。後からQuick Lookは開かなかった。
2. 取消後に通常PDFを再試行し、3ページのQuick Lookで先頭・後半・最後の各セクション、担当者、フッターを目視確認。[画面証拠](meeting-pdf-2026-10-ios.png)。
3. ライブラリの既存サンプル「リリース方針レビュー」から、通常の会議詳細 → その他 → PDFで共有を実操作。PDFが標準共有画面へ渡り、閉じると操作可能な会議詳細へ戻った。外部アプリへ送信・保存はしていない。
4. 検証用の会議をSQLiteへ追加せず、既存記録は編集・削除していない。自己チェック失敗ログは0件。

`bitrig preview -platform iOS`: success。ログは `2026-10-31T02-35-30-d76787b3.log`。警告11件は既存のMapKit/OAuth/AppIntents由来で、今回の変更箇所の新規警告はない。
