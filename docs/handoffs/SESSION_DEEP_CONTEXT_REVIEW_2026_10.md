# 深い文脈・資料品質の独立レビュー（2026-10-30）

対象: `SESSION_DEEP_CONTEXT_2026_10.md` と開始時HEAD `f07d40b0` の実装・成果物。
main、開始時の未コミット変更なし。実装を読み、既存検査を再実行し、回帰検査を追加した。

## 判定

従来の「機械検査0件」は資料の内容品質を保証していなかった。
基本的な組版・編集可能なPPTX・出典情報の保持には土台があるが、
参照範囲、意思決定の扱い、数値の意味、検証fixture自体の論理に修正が必要だった。
以下は修正済み。実LLMの文章品質や全65型のOffice実描画まで合格したとは判断しない。

## 修正した問題

| 優先度 | 観察した問題 | 対応 |
|---|---|---|
| 高 | 深い依頼の根拠パックが、指定プラグインの参照制限と無関係に全体を収集する | 明示的な実行ポリシーがある依頼では自動の横断パックを追加せず、既存の制限付きツール経路を使う |
| 高 | 人物の担当タスクを個別権限なしで引用する。プロジェクト指定でも他のタスクを収集する | タスク権限とプロジェクトを先に絞り、人物の引用にも同じ集合を使う |
| 高 | ジャーナルの親記録・種類の制限を通さず、直接privacyだけを検査する | 既存の `allowsJournalAccess` を使う |
| 高 | 独立した送信許可のない保存資料を `permission: allowed` としてクラウドに渡す | 既存のプロジェクト検索と同じく自動クラウド参照から除外。必要な前回資料は明示的な添付経路を使う |
| 高 | 読み取ったタスク・人物・ジャーナルと、人物経由の会議がセッションの出典追跡に入らない | 各出典の依存IDを保持し、全種類を `recordCloudReads` へ登録。品質画面の権限警告も依存元を確認する |
| 高 | 未決・保留を有効な決定として扱う。新しい提案が承認済みの方針を消す | 未決は有効から除外、提案は既存承認を置き換えない。未承認・否定表現の一部も保留として扱う |
| 高 | 全記録の決定主題を検索語に加え、無関係な最終版にも点を与える | 依頼に基づいて関連性を評価してから最終版を優先。採用出典の決定のみ渡す。依頼そのものの語は頻出を理由に捨てない |
| 中 | 草稿を `previousFinalDeck` に入れる。前回差分に全記録の数値が入る | 関連する最終版だけを採用し、採用した新しい出典だけと比較する |
| 高 | 一行の金額・率・日付・型番を一つの指標と単位にまとめる | 単位付きの数量を一つずつ抽出。万円・%・時間/月などを保持し、年・ページ番号・型番を数量から除外 |
| 中 | 根拠本文の抜粋外から数値・リスクだけが追加される | 数値・リスクも採用した抜粋から作る |
| 中 | 抜粋の文字数だけを予算化し、決定・警告・差分の分だけ上限を超える | 描画した根拠パック全体に予算を適用し、出典単位で縮小。0/100/600/2,000文字の境界を検査 |
| 中 | 名前の部分一致で別人の発言を帰属する | 話者名の完全一致を使い、同姓同名が複数いれば発言を帰属しない |
| 中 | 処理済みの会議を自動で「確認済み」の事実と呼ぶ | 処理状態と事実確認を区別し、「記録あり」として送る |
| 高 | 順位横棒が負数も正方向へ描き、複数系列を渡すと先頭以外を黙って捨てる | ゼロ基準で負数を左に描く。対応する1系列の棒グラフだけを入力として受け付ける |
| 高 | 合計不一致の検査がm08だけで、m07/b23などに効かない | 絶対合計を指定したすべてのブリッジで算術検査する |
| 中 | Validatorが常にページ番号1で検査。旧形式の分割ページの後で番号がずれる | 実際の派生ページ番号を使い、混在資料と大きな番号の回帰検査を追加 |
| 中 | シナリオPDF/PNGがページ番号を渡さず、本番の派生ページと異なる | シナリオも `SlidePageLayout.pages(for:)` を使う |
| 高 | 保存した根拠にないスライドの数量を検査しない | 指標・グラフ・表・主張文の単位付き数量を抜粋と比較し、見つからないものを品質画面で注意表示する |
| 低 | Jinba比較レポートの表区切りと先頭行が連結する | レポートと生成スクリプトの改行を修正 |

数量照合は「同じ数値・単位が抜粋にあるか」の確認であり、指標名・期間・因果関係の正しさを保証しない。
通貨や桁の単位換算、計算で導いた値、未対応単位は原資料で確認する必要がある。
数値の追加を一律に禁止すると試算まで書けなくなるため、注意は保存を妨げない。

## 残る限界と次の優先順位

1. **実モデルの内容評価**: 原記録→主張→数量→提案を採点する実LLMの受入検査は未実施。
   現行のシナリオ0注意を、モデルが正しく資料を作れるという証拠にしない。
2. **決定の主題・時点**: 会議名と文頭からの主題推定は依然として字句ベース。
   異なる言い回しの承認・変更を常に同じ系列へ結べない。明示的なsupersedesがない実データでは現行性の確認が必要。
3. **数量の意味**: 単位を保持しても期間・指標・因果の一致までは判定しない。
   過年度との違いを矛盾候補として警告する場合もあり、単位換算・期間別の構造化が次の改善候補。
4. **端末内に残る抜粋**: 生成時の根拠パックと完成資料はSQLite/個人バックアップに残す。
   クラウド許可取消はローカル文書の削除ではない。自動再送の経路は閉じたが、
   抜粋の明示削除やバックアップ除外のUIは未実装。元の資料本文まで自動で消したとは扱わない。
5. **既存資料の自動再利用**: 外部送信許可がない保存資料はクラウド根拠に使わない。
   自動で前回版を再利用するには、資料固有の送信許可・内容版・元出典の検証が必要。
   明示的な実行ポリシー付きの依頼にも、今は横断パックを追加しない。
6. **見た目の最終評価**: Jinbaとの全65型比較、Office/Keynote描画、実機VoiceOverは未実施。
   旧アウトラインのページ番号自体は今回追加していない。後続する構造化ページの番号は実ページへ揃えた。
7. **モデル上限・長期実行**: 実トークナイザー・提供元の上限/料金確認は未実施。
   送信コピーの圧縮は全量が必ず窓内に入る保証ではなく、ローカルのmessagesも増える。
   出力上限・リクエスト上限は残っているが、長時間実機のメモリ計測は別途必要。
8. **表現力・復旧・CI**: ネイティブチャートやリッチテキスト、調査途中の復旧、
   自動CIは元の引き継ぎどおり未実装/手動運用。今回の修正ではサービス・料金・CI設定を変えていない。
