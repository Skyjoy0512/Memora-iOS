# コミュニティ・共有・コネクタ・テンプレート改訂 — 2026-10-31

## 依頼と範囲

マーケットプレイスのデザインを維持し、他の人の投稿・いいね・ダウンロード指標、
スキル/テンプレートの共有、Ask AIの＋とマーケットプレイスのコネクタ導線、テンプレート内容を改善した。
公開基盤について利用者に確認し、「まだない。Firebase等で使えるように考えて実装」と回答を受けた。
CloudKitの導入や恒久バンドルID変更は行っていない。

## 実装

### Firebaseコミュニティ

ホームの注目カード直下からコミュニティへ。人気/新着、自分の投稿、実カウンターを表示する一覧、
手順と必要ツールを読める詳細、追加、いいね、報告、投稿者の非表示、投稿の取り下げを追加した。
投稿は詳細のメニュー、または＋の「コミュニティに投稿」から選択できる。
公開する本文・投稿者名を確認し、公開ルールへの同意後に審査へ送る。

`backend/marketplace`にデプロイ可能なFirebase Functions、Firestoreルール/インデックス、
検証済みメールのAuthトークンを扱うサーバーAPIと、SwiftのRESTクライアントを追加。
これは現在のMemoraAccountやプラン/チームバックエンドを偽装するものではなく、コミュニティ専用認証。
パスワードは保存せず、更新トークンはKeychain。管理者キーはアプリへ渡さない。

本文・上限・ツール許可リストをサーバーとアプリの両方で検査。投稿者/状態/数値はクライアント入力で上書きできない。
投稿は審査待ちから開始。いいねは希望する状態を送信し、アカウント/投稿単位で重複排除する。
ダウンロードは定義の取得後、ローカル保存成功の確認と取得レシート/版の一致後に加算。
繰り返し追加しても同じアカウントからの加算は1回。編集中のワークスペースが変わった場合は保存しない。
既に取り込んで編集した項目は再取得で上書きしない。保存成功後に集計だけ失敗した場合は画面から再試行できる。
この再試行待ちは画面内の状態であり、画面を閉じた後までの集計再送キューは追加していない。

サーバーは新規投稿10件/アカウント/日、リアクション等200件/日。
人気順はサーバーの `いいね×3＋追加数`、新着はサーバー時刻。20件のページ方式。
報告はアカウントごとに重複を避け、異なる3アカウントの報告で隔離する。取り下げは投稿者本人だけ。
審査・通報対応は管理者が行う。アプリ自身で公開済み状態に変更できない。

**Firebaseプロジェクト未作成・未接続**のため、実際の公開や複数人での集計はまだ稼働しない。
構成キーがないビルドは準備中を表示し、サンプル投稿や架空の人気数を埋めない。
接続・運用・検証手順は [バックエンドREADME](../../backend/marketplace/README.md)。
Bitrigの利用可能プラグインにはFirebase専用コネクタがなかったため、SDKなしの公式REST/API経路を用意した。

### ローカル共有

スキルとテンプレートの詳細メニューに共有を配置。共有するのは定義だけで、会話・記録・鍵は含まない。
共通JSONと従来のスキルMarkdownを32KB以内で読み込み、既存エディターで確認してから保存できる。
取り込みIDは新しくし、外部の定義で既存項目を勝手に更新しない。
旧スキルのID依存ツール指定も明示的な宣言へ変換し、共有後に欠落しないようにした。

### コネクタ

Ask AIの＋→コネクタと、マーケットプレイスのカード/検索/全件から共通のコネクタ画面へ。
接続済み、未接続のおすすめ、準備中を分け、アイコン・できること・接続の主操作を先に表示。
詳細はネイティブのシート。Gmail/Notion/MCPの既存設定、端末カレンダーの許可へ接続した。
「接続済み」と「Ask AIで使う」を分け、利用をOFFにしても既存の接続を失ったように表示しない。
設定画面から戻った時、シートを閉じた時、アプリ復帰時に実際の接続状態を確認し直す。
Gmailの検索構文や内部ツール名を主画面に並べず、利用者向けの能力名に置換した。
未実装のDrive/GitHubは準備中のまま。実在しないOAuth接続を追加していない。
権限とツール実行時の確認、カレンダーの承認失効、IME/添付/下書きの既存経路は維持する。

### テンプレート内容の監査

対象: 組み込み4形式、マーケット43形式。保存済みID、カスタムテンプレート本文は維持。
医療/介護/現場/個人の18用途別テンプレートは元々原文と推測を分け、行動抽出を無効にしており、その方針を維持した。

| 対象 | 判定・修正 |
|---|---|
| 定例/デイリー/経営/進捗 | 未報告を未着手としない。実績・予測・目標を分離。理由・対策・支援者・責任者を補わない |
| 意思決定/交渉/提案/キックオフ/要件 | 決定・提案・保留、合意済みと未確認を区別。元の型・数値の保持方針を維持 |
| ブレスト/KPT | AI独自の推奨・順位を作らず、実際の評価・Tryの提案と合意を分ける |
| 商談 | 未言及は「記載なし」。当事者が未定と述べた内容だけ「未定」。受注見込みを推測しない |
| 顧客ヒアリング | 既に確認事項の章があるため、汎用の「未決事項」を重ねない |
| 1on1/評価/採用 | 本人の発言と評価者の所見を分ける。AIが評点・適性・総合所感を創作しない |
| セミナー/講演/学習/取材 | 会議用の未決事項や決定/タスクを付加しない。「自分の業務への活かし方」を「紹介された活用例」へ |
| ユーザーインタビュー | 発言・行動・解釈を分け、少数の意見を全利用者へ一般化しない |
| 動画/配信 | 視聴用の専用構成、時刻不明、会議の決定/タスクにしない契約を維持 |
| カルテ/施術/介護/申し送り/事故/日報/現場/点検/接客/学習/生活/技術/配送/授業/相談/生育/研究/買い物 | 各用途固有の章、原文にない状態や行動を足さない指示、個人/機微区分を確認し維持 |

共通プロンプトにも未言及と保留の区別、AI独自の助言を記録の事実へ混ぜない指示を追加した。
これはプロンプトと構造の監査であり、実モデルの出力品質を保証したという意味ではない。
