# データ保護の修正 — 2026-11-10

## 録音とメディア削除

- 連続録音のマイク失敗通知は開始時のrunIDを保持する。古い録音の通知は、
  現在の録音・診断結果・マイク・監視タスクを変更しない。
- 写真の参照更新と削除予約を同じSQLiteトランザクションに含める。
  Undoも参照復元と予約解除を同時に保存する。
- 写真・音声のUndo保存が失敗した場合は、取り消し操作を残して再試行可能にする。
  失敗後は自動期限切れによるメディア削除を行わない。次の削除操作が置き換える場合は
  既存の確定処理に従う。
- 写真の削除・再試行前に、会議・日記・両方のゴミ箱の参照を確認する。
  別の記録が所有している写真は消さない。

検証: `run-recording-media-checks.py`は本番のメディア処理・Undo処理と実SQLiteを使用。
削除予約の書き込みをトリガーで拒否し、削除／Undoのロールバック、再読み込み、
再試行を確認。写真削除はspyで、所有中の写真が削除に渡されないことを確認する。
`run-recording-checkpoint-service-checks.py`は本番の失敗ハンドラーを抽出し、
旧録音の遅延通知を新録音の開始後に配送する。現在の録音の失敗通知は一度だけ反映。
実マイク・OSの通知タイミングは未検証。
