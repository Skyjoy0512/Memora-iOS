# Memora — 改善バックログ

レビュー指示書の項目ごとの状態。状態は次の4つだけを使う。

- **未着手**: コードに入っていない。
- **実装済み・未検証**: コードに入っているが、実機・シミュレータ・外部サービスでの
  確認が済んでいない。性能の数値は「未計測」と明記する。
- **検証済み**: 実機・シミュレータで受け入れ条件を確認済み。何で確認したかを書く。
- **保留**: いまは行わない。理由と解除条件を「保留の理由」に書く。

※ 過去のレビューではシミュレータの状態APIが利用できなかった。今回、状態APIによる
ジャーナルから振り返り画面への遷移と日次集計の表示を確認した。これ以外の既存項目の
検証状態を一括で変更するものではない。

## 今回の追加反映: 読みやすさ・タスク・振り返り・Ask AI

- **実装済み・未検証（実APIが必要）**: Ask AIのクラウド主担当が`delegate_research`で
  1依頼を2〜3担当へ分担できる。分担内容・対象範囲・追加API利用を確認するカードで承認後、
  独立したクラウド会話を並列実行し、主担当へ報告して1つの回答へ統合する。
  子担当は記録検索・読み取り・タスク一覧・期間集計のみ。全体範囲でGmail連携済みの場合だけ
  メール検索・読み取りも許可。書き込み・MCP・再分担・健康データ取得は許可しない。
  変更は主担当が通常の確認カードで別途承認を得る。分担開始の承認はデータ変更として記録しない。
  1依頼につき1分担、最大3担当、各最大6往復、1往復4ツールまで。失敗・中止・上限を報告し、
  完了した担当だけの結果でも未完了を明示して統合する。依頼／ワークスペース変更は停止する。
  現在はBYOKクラウドのみ。同じ依頼で選択されたモデルを固定して使う。
  担当の固定プロフィール・個別履歴・バックグラウンド実行・自動再試行は今回の対象外。
  Bitrigビルド成功。独立チェックで分担数・重複・空欄・型・長さの検証を確認。
  実際のクラウドAPIでの並列実行・統合・承認拒否・途中停止・部分失敗は未検証。

- **検証済み（自動表示の導線）**: ジャーナルの日付選択直後に日次の概要を表示。
  今日は「今日はここまで」、過去日は「こんな1日でした」、未来日は予定として扱う。
  会議・録音、日時のある完了タスク、メモ・写真・場所・登録イベントを記録から集計し、
  時間順の見どころを最大3件表示。サンプルと未来の活動は振り返りから除外する。
  クラウド生成・保存・健康権限の要求は自動実行しない。詳細画面は引き続き任意で開ける。
  Bitrigビルド成功。シミュレータで今日の空状態と過去日の録音1件の概要を確認。
  DEBUG自己チェックに完了日時不明・未来のイベント・未来日・空の過去日の境界を追加。

  座標の欠落・範囲外・非有限値の独立チェックを追加。
  実機の位置権限拒否、再起動／復元、長い一覧、文字サイズ拡大、VoiceOverは未検証。
  AI送信範囲・常時追跡・移動経路推測は変更しない。

- **実装済み・未検証（ビルド成功）**: 要約・回答の短い段落、選択的な太字、概要の追加、
  Markdownの行間と安定したストリーミング表示。回答の資料保存、44pt操作領域。
- **実装済み・未検証（ビルド成功）**: タスクの説明・取り組む日・進み具合を保存。
  今日／相手待ちの絞り込み、空結果からの解除。Ask AIは最大30件を変更前後の確認後に
  一括保存する。期限・担当・本文は変更せず、確認中の編集・ワークスペース変更では停止。
- **検証済み（導線と日次表示のみ）**: ジャーナルの「選んだ日を振り返る」から
  振り返り画面を開き、日次集計・前日比較・初期オフの健康設定をシミュレータの状態APIで確認。
- **実装済み・未検証（ビルド成功）**: 日／週の全件集計、前日／前週比較、記録された場所、
  個人メモ用の資料保存。資料保存では健康と位置情報を含めない。自動週報の再生成は
  生成部分が未編集の場合だけ差し替え、末尾に追記したメモを保つ。
- **実装済み・未検証（実機が必要）**: HealthKitの歩数・睡眠・ワークアウトを
  明示的な読み込み操作後に表示。健康データはメモリ内のみで、AI・チーム・Webhook・
  バックアップに含めない。未取得と拒否を推測で区別しない。睡眠と運動は期間で切り、
  重複区間を一度だけ数える。個人ワークスペースだけに導線を出す。
- **実装済み・未検証（外部サービス／障害試験が必要）**: Webhookテストはダミーのみ。
  ごみ箱の完全削除と期限切れ整理は、記録削除とメディア削除ジョブを同じ保存にまとめる。
- **検証記録**: Bitrigビルド成功。起動時DEBUG自己チェックで追加したタスク互換性・

  終日イベントのテスト入力が開始・終了とも同時刻だったことが原因。終了を翌日の

### 継続改善: タスク保存とAI入力の検証

- タスクの追加・完了切替・編集・期限変更・取り組む日変更・削除・削除の取り消しは、
  保存が成功してからモデルと通知を更新する。失敗時には未保存の状態を画面に出さない。
  編集・追加・削除の画面は失敗時に閉じず、再試行できる。
- Ask AIの複数タスク追加は1回の保存にまとめ、途中だけ追加する状態を避ける。
  入力は1〜30件。空タイトル、無効な日付、対象外の会議では全体を拒否する。
  承認後のキャンセル・ワークスペース変更・元会議の削除も再確認する。
- 取り組む日は編集時に明示的に指定し、未指定の呼び出しが既存の値を消すことを防ぐ。
- 検証: Bitrigビルド成功、差分の空白検査成功。新しいタスク保存処理の実際の
  ディスク障害・通知・Undo連動と、クラウドモデルによるツール実行は未検証。

## 修正: 文字起こしの表示（進行結果の混入）

- 症状: 文字起こしが「こ」「こん」「こんに」…と1文字ずつ行になり、同じ文が何行にもなっていた。
- 原因: `SpeechAnalyzerTranscriber` が `SpeechTranscriber.results` の**進行途中の結果も1件ずつ保存**していた（`.timeIndexedProgressiveTranscription`）。
- 修正: 文の開始時刻ごとに最新の結果だけを残し、`isFinal` を優先する `SpeechTranscriptionCollapse.collapse` を通す。**確定しなかった進行（途中で切れた録音）は最後のテキストを保持**する。
- 既存データ: **起動時の自動修復は行わない**（T01）。旧データには途中結果と正常な発言を区別する情報がなく、
  話者・手編集・生成元も見ていないため、推測で書き換えると発言を消し得る。既存の文字起こしは**そのまま保持**する。
  復旧は実際のバックアップまたは元音声からのやり直しによる。
- 自己チェック: 進行の畳み込み（1文→1行、時刻保持、未確定の保持）。
- 状態: **実装済み・未検証**（ビルド成功。実機での再文字起こしと既存記録の表示は未確認）。
- **T02（実装済み・未検証）**: 保存済み音声は一度だけ処理するため、`SpeechTranscriber` を
  **`reportingOptions` に `.volatileResults` を含めない設定**へ変更（暫定結果を要求しない）。`attributeOptions: [.audioTimeRange]` で時刻を保持。
  確定結果だけを1件ずつ行にする `SpeechTranscriptionSegments.segment(from:)` に置き換え、**近接時刻・同一文言を理由に統合・削除しない**
  （同じ「はい」が2回なら2行）。全途中結果を貯める配列と推測的な統合（`SpeechTranscriptionCollapse`）は削除。
  結果は **正常（発言あり）／認識対象なし／キャンセル／非対応／失敗** を区別し、いずれの場合も**元音声は保持**。
  キャンセル時は処理中表示を残さず「未開始」に戻す。
- **T03（実装済み・未検証）**: 収集Taskは全経路で終了し（`defer { collect.cancel() }`）、
  解析セッションは失敗・キャンセル時に `cancelAndFinishNow()` で閉じる。結果収集後に
  親のキャンセルを検知した場合は `cancelled` を返し、部分結果を適用しない。

## 保留の理由と解除条件

- **A01（デモと実データの分離）**: 独立ストア（A07）と同時に行うのが安全。
  解除条件: ローカルストア導入時にデモを別領域へ移す。
- **A06（復旧・書き出し）**: バックアップ基盤（フェーズ2）が必要。
  解除条件: バージョン付き書き出しパッケージの実装。
- **E01（safe areaのルート整理）**: 全主要画面の確認が必要で、シミュレータの
  状態APIが復帰してから検証する。解除条件: 実機/シミュレータでの確認。
- **CloudKitチーム共有の実機稼働（今回は保留）**: コード（`CloudSharingService`、
  プロジェクト/会議単位の共有、受信一覧、subscription）は実装済みだが、
  Apple Developer Program（年額）のアカウント接続とiCloudコンテナ/entitlementが
  必要。未接続の間はアプリが「iCloudコンテナが設定されていません」等を表示する。
  解除条件: Project Settings > Distribute にアカウントを接続し、バンドルIDの割り当て、
  コンテナ作成、`MemoraSharedItem` スキーマの配備、実機での共有確認を行う。
  それまでは手動のパッケージ書き出し（`makeTeamSharePackage`）のみ利用可能。
