  保存が成功してからモデルと通知を更新する。失敗時には未保存の状態を画面に出さない。
  編集・追加・削除の画面は失敗時に閉じず、再試行できる。
- Ask AIの複数タスク追加は1回の保存にまとめ、途中だけ追加する状態を避ける。
  入力は1〜30件。空タイトル、無効な日付、対象外の会議では全体を拒否する。
  承認後のキャンセル・ワークスペース変更・元会議の削除も再確認する。
- 取り組む日は編集時に明示的に指定し、未指定の呼び出しが既存の値を消すことを防ぐ。
- 検証: Bitrigビルド成功、差分の空白検査成功。新しいタスク保存処理の実際の
  ディスク障害・通知・Undo連動と、クラウドモデルによるツール実行は未検証。

## 修正: 文字起こしの表示（進行結果の混入）

- 症状: 文字起こしが「こ」「こん」「こんに」…と1文字ずつ行になり、同じ文が何行にもなっていた。
- 原因: `SpeechAnalyzerTranscriber` が `SpeechTranscriber.results` の**進行途中の結果も1件ずつ保存**していた（`.timeIndexedProgressiveTranscription`）。
- 修正: 文の開始時刻ごとに最新の結果だけを残し、`isFinal` を優先する `SpeechTranscriptionCollapse.collapse` を通す。**確定しなかった進行（途中で切れた録音）は最後のテキストを保持**する。
- 既存データ: **起動時の自動修復は行わない**（T01）。旧データには途中結果と正常な発言を区別する情報がなく、
  話者・手編集・生成元も見ていないため、推測で書き換えると発言を消し得る。既存の文字起こしは**そのまま保持**する。
  復旧は実際のバックアップまたは元音声からのやり直しによる。
- 自己チェック: 進行の畳み込み（1文→1行、時刻保持、未確定の保持）。
- 状態: **実装済み・未検証**（ビルド成功。実機での再文字起こしと既存記録の表示は未確認）。
- **T02（実装済み・未検証）**: 保存済み音声は一度だけ処理するため、`SpeechTranscriber` を
  **`reportingOptions` に `.volatileResults` を含めない設定**へ変更（暫定結果を要求しない）。`attributeOptions: [.audioTimeRange]` で時刻を保持。
  確定結果だけを1件ずつ行にする `SpeechTranscriptionSegments.segment(from:)` に置き換え、**近接時刻・同一文言を理由に統合・削除しない**
  （同じ「はい」が2回なら2行）。全途中結果を貯める配列と推測的な統合（`SpeechTranscriptionCollapse`）は削除。
  結果は **正常（発言あり）／認識対象なし／キャンセル／非対応／失敗** を区別し、いずれの場合も**元音声は保持**。
  キャンセル時は処理中表示を残さず「未開始」に戻す。
- **T03（実装済み・未検証）**: 収集Taskは全経路で終了し（`defer { collect.cancel() }`）、
  解析セッションは失敗・キャンセル時に `cancelAndFinishNow()` で閉じる。結果収集後に
  親のキャンセルを検知した場合は `cancelled` を返し、部分結果を適用しない。
