# 常駐エージェントの停止・待機列・完了判定

## 修正

- 自動実行の待機列を、設定・ワークスペース・参照許可・BYOKモデルの世代へ結び付ける。
  待機中に無効化／削除／編集したジョブを、再有効化や再追加で復活させない。
- 設定変更時は実行中タスクをキャンセルする。モデル応答と各読み取りツールの前後、
  結果を採用する直前にも確認し、失効した結果を投稿・履歴保存・実行済み扱いにしない。
- 停止したタスクが終了するまでは同じエージェントの実行枠を保持する。
  古い完了通知が後続処理の実行枠を消さない。
- 通知権限の取得後にも設定を照合し、通知登録中に失効した場合はその通知を除去する。
  既に有効な状態で投稿済みの結果は履歴に残す。
- 「今すぐ実行」は自動実行オフでも、保存済みエージェントの編集途中の指示を試せる。
  保存時にエディタの古い実行日時を戻さない。
- 完了メッセージ更新のinout内から同じ配列を読み直す排他アクセス違反を修正。
  ホスト検査でクラッシュを再現し、修正後の完了まで確認した。

## 検証

`run-resident-lifecycle-checks.py`は本番の待機／実行／採用／通知メソッドを使用する。
24条件のモデル／ツール待機中の停止、4条件の自動実行待機列の失効、
手動実行・編集下書き・実行日時保持・停止中の二重起動拒否、通知の権限確認／登録待機を検査。
iOSプレビュー更新と`run-next-generation-checks.sh`の広域回帰が成功。
LLM通信・OS通知・バックグラウンドスケジューラ・モデル保存はfixtureであり、
実API・実通知・実機でのバックグラウンド実行を検証したものではない。
