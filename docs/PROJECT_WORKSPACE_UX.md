# プロジェクトの導線と関連タスク — 2026-10-15

## 変更した体験

| 場面 | 変更前 | 変更後 |
| --- | --- | --- |
| 資料があるプロジェクトに追加 | その他メニューから追加 | ソース見出しの「追加」から1タップ |
| 資料がない | 常設の説明2行と大きな空白 | 件数・追加操作・短い空状態 |
| 大きい文字 | 見出しと操作が常に横並び | accessibilityサイズでは縦並び |
| 全ソース/チャット | 一覧の画面名が空 | ネイティブのタイトルで現在地を表示 |
| 関連タスクの「すべて」 | 全体の自分用TasksViewへ遷移 | 対象プロジェクトの記録に紐づく全担当のタスクを表示 |
| 完了タスクの確認 | 未完了一覧から届かない | 関連タスクの表示メニューで完了分も表示 |
| タスクの出典 | VoiceOverの補助情報が中心 | 各行に元記録の名前と44ptの移動操作 |
| プロジェクト内の検索 | 下部コンポーザー/タブが残る | 結果だけにし、キャンセルで既存UIへ復帰 |

チャット、ソース、関連タスクという情報の順序と、既存3件のプレビューは維持。
資料の解析/参照状態は既存`ProjectSourceRow`を使う。保存件数をAIによる理解済み件数と
表示しない。カードやGlassは増やさず、常時表示のプロンプト/キャラクターも追加しない。
新規チャット、既存の保存会話、メニューからの未決事項質問は従来の経路を使う。

## 再利用と境界

- `TaskRow`の完了操作、`TaskEditView`の編集/保存、`MeetingDetailView`へのvalue遷移を再利用。
  タスクの作成は既存の記録詳細とHomeの作成経路を維持する。
- `ProjectTaskList`の選択は、現在のプロジェクトにある記録IDから行う。
  自分/他の担当/担当未定を含むが、全体タスク・別記録・所属のないタスクは補充しない。
  AIのデータ権限や送信許可を付与する仕組みではない。
- `LibraryRoute.projectTasks(UUID)`は既存NavigationStackへの追加。
  `RootNavigation`でproject IDとAI scopeを維持し、出典を開いたときはrecord scopeにする。
  グローバルAsk AI、Homeの自分のタスク、shared projectのread-only経路は維持する。
- 検索を覆う判定だけを`RootNavigation.searchCoversScreen`へ抽出。
  RootTabViewはこの判定の呼出しに限って変更する。Files/Journalの検索とファイル選択、
  検索結果から開いた詳細の表示は維持する。UISegmentedControl/FAB/Glass/アニメーション/
  safe area/コンポーザー本体は変更しない。
- 追加UIは`ProjectSectionHeader`、`ProjectTaskRow`、`ProjectTasksView`。
  セクション見出しとタスク行は詳細プレビュー/一覧で共有する。表示のための新しい
  保存領域、モデル、外部ライブラリは追加しない。

## ローカル操作の検証画面

DEBUGの設定→プロトタイプ→状態と復旧UI→「関連タスク（範囲と保存の検証）」。
`ProjectTaskOperationCheck`は音声やLLMを使わず架空の記録2件/タスク6件を
通常のSQLiteへ追加する。対象は未完了3件/完了を含め4件、対象外は2件。
本体と同じProjectTasksView、TaskEditView、完了保存、出典遷移を実行できる。
編集後は現在の検証タスク集合とSQLiteの再読込集合を比較する。

親画面が所有するIDだけを、閉じる際または明示操作で原子的に削除する。
検証プロジェクト/記録に他の内容が追加された場合は削除を拒否する。
アプリ強制終了時の自動削除までは保証しない。検証中にbuild/再起動しない。
実モデルの応答・実録音・実サービスのE2Eを検証した画面ではない。
