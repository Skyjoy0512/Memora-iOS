### F01 他のアプリの音声を「Memoraで開く」で受け取る

**現状**: `Project.json` に文書の種類の宣言（`CFBundleDocumentTypes`）がない。そのため、ファイル・ボイスメモ・メールなどの共有シートに Memora が出ない。`App.swift` の `onOpenURL` → `model.handle(_:)` は `memora://` しか扱わない。

**実装**:
- `Project.json` の Info.plist に次を追加する（`bitrig-standard-project` の規則に従う）。
  - `CFBundleDocumentTypes`: `public.audio`（と `public.mpeg-4-audio`、`com.apple.m4a-audio`）、`LSHandlerRank` は `Alternate`。
  - `LSSupportsOpeningDocumentsInPlace = false`（コピーして取り込む）。
- `MemoraModel.handle(_:)` で、`url.isFileURL` のときはセキュリティスコープの開始と終了を行い、既存の `importAudio(from:)` に渡す。取り込み後はファイルタブのその記録を開く（`importAudio` の既存の遷移を使う）。
- 複数の音声を一度に受け取った場合は、順番に取り込む（UX16 の「複数インポート」と同じ処理を共有する）。
- 録音中は受け取りを保留し、録音が終わってから取り込む（「録音が終わったら取り込みます」と表示する）。

**受け入れ条件（シミュレータで確認）**:
- ファイルアプリで音声ファイルを長押し → 共有 → 「Memora」を選ぶと、取り込まれて文字起こし待ちの記録として開く。
- 音声以外のファイルでは、共有シートに Memora が出ない。
- 読めない音声は、既存の「インポートできませんでした」のアラートで理由を示す。

### F02 録音中のリアルタイム文字起こし

**現状**: 録音シートの「文字起こし」タブは「録音を終えると文字起こしします」と表示するだけ（B08）。

**実装**（iOS 26 以降・端末内の `SpeechAnalyzer` が使えるときだけ）:
- 録音中の音声バッファを、`SpeechTranscriber`（`reportingOptions` に `.volatileResults` を含める）へ `AnalyzerInput` として流す。録音のファイル書き込みとは別の経路にし、**録音そのものを妨げない**（文字起こしが遅れても、失敗しても、録音は続く）。
- 録音シートの「文字起こし」タブに、確定した行と、確定前の行（薄い色）を表示し、最新の行へ自動でスクロールする。
- 録音を終えたあとの正式な文字起こしは、今までどおり保存済みの音声から行う。リアルタイムの結果は表示専用とし、保存しない（二重の文字起こしで内容が食い違うのを避けるため）。
- 使えない環境（iOS 25 以前、非対応の言語、クラウドを選んでいる）では、今の案内文を出す。クラウドへリアルタイムで送ることはしない。
- 電池と発熱を考え、設定に「録音中に文字起こしを表示」の Toggle を置く（既定オン）。

**受け入れ条件**:
- 実機で録音中に話すと、数秒以内に文字起こしタブへ文字が出る。
- リアルタイムの文字起こしを止めても、録音の音声は欠けない。
- 録音を終えると、保存済みの音声から正式な文字起こしが作られる（リアルタイムの結果では上書きしない）。

### F03 アプリのロック（Face ID / Touch ID / パスコード）

**実装**:
- 設定の「プライバシーと保存」に「Face IDでロック」の Toggle を置く（既定オフ、UserDefaults に保存）。
- オンのときは、アプリが前面に来たとき（起動時、および5分以上バックグラウンドにいたあと）に `LAContext.evaluatePolicy(.deviceOwnerAuthentication, …)` で認証を求める。認証が済むまで、中身の上に不透明なロック画面（アプリのアイコンと「ロックを解除」ボタン）を重ねる。
- アプリ切り替えの画面に中身が映らないよう、`scenePhase` が `.inactive` になったらすぐに目隠しを重ねる。
- 録音中はロックしない（録音シートの操作を妨げないため）。Live Activity から戻ったときも、録音中ならロックしない。
- `NSFaceIDUsageDescription` を `Project.json` に追加する。「記録を他の人に見られないよう、Face IDでMemoraのロックを解除します。」

**受け入れ条件**:
- オンにしてアプリをバックグラウンドへ送り、5分後に戻ると、ロック画面が出る。解除すると元の画面に戻る。
- アプリ切り替えの画面で、記録の中身が見えない。
- 録音中にアプリを切り替えて戻っても、ロックされない。

### F04 保存容量の管理（音声だけ削除）

**実装**:
- 設定の「プライバシーと保存」に「保存容量」の画面を追加する。音声・写真・その他の使用量（`MediaFiles` の管理フォルダを集計）と、記録ごとの音声の大きさを、大きい順に表示する。
- 会議の詳細のメニューと、この画面の各行に「音声を削除（文字起こしと要約は残す）」を置く。確認ダイアログを出してから `audioURL` を外し、ファイルを削除する。UX05 の取り消しを効かせる（ファイルの削除は `pendingMediaDeletions` で確定まで遅らせる）。
- 音声のない記録では、再生ボタン・再生バー・「文字起こしをやり直す」を隠し、「音声は削除済み」と表示する。
- 一括の操作として「90日より前の記録の音声を削除」を置く（件数と空く容量を示して確認する）。

**受け入れ条件**:
- 音声を削除しても、文字起こし・要約・ノート・タスクは残る。
- 使用量の表示が、削除した分だけ減る。
- バックアップの書き出しは、音声のない記録も正しく扱う（参照の欠落として失敗にしない）。

### F05 繰り返しの予定を、同じプロジェクトへ自動で振り分ける

**実装**:
- 予定から録音した記録（`Meeting.calendarEventID` がある）をプロジェクトに入れたとき、その予定が繰り返しなら「今後もこの予定の録音を『プロジェクト名』に入れますか？」と一度だけ尋ねる。
- 「入れる」を選んだら、予定の繰り返しの系列（`EKEvent.calendarItemIdentifier`、なければタイトルとカレンダーの組）とプロジェクトの対応を保存する。記録ではなく設定に近いので `UserDefaults` に保存する。
- 以後、同じ系列の予定から録音を始めると、保存したときに自動でそのプロジェクトへ入れる。録音シートに「『プロジェクト名』に入ります」と表示し、その場で変えられるようにする。
- 対応の一覧と解除は、プロジェクトの詳細のメニューに置く。

**受け入れ条件**:
- 毎週の定例の予定から録音 → プロジェクトに入れる →「今後も」を選ぶと、翌週の定例の録音は自動でそのプロジェクトに入る。
- 単発の予定では、尋ねない。

### F06 週のふりかえり

**実装**:
- ジャーナルの週表示のとき、週の見出しの横に「この週をふりかえる」を置く。押したときだけ AI を使う（自動では実行しない）。

**受け入れ条件**:
- 押したときだけ生成され、生成中は取り消せる。
- 材料にした会議へのリンクが、根拠として付く。

### BL01 入力欄を Ask AI タブと会議の詳細だけにする

- TB04 で入れた「一覧タブの全体への質問を Ask AI の会話へ送る」分岐は、一覧タブに入力欄がなくなるので不要になる。削除して、Ask AI タブの送信だけを残す。
- `DESIGN.md` の E「Navigation」と H「AI composer」の記述を直す。
- **受け入れ条件（シミュレータで確認）**:
  - ファイル・ジャーナル・タスクに入力欄がない。
  - Ask AI タブでは、入力欄が画面幅いっぱいで、タブバーの上に隠れずに出る。

### BL02 下部の要素の大きさをそろえる
今の大きさ（9b95291 時点）は次のとおりで、形と高さがばらばらになっている。

| 要素 | 今の大きさ |
| --- | --- |
| タブ | 高さ 52＋上下の余白 2 = 56 |
| 「＋」 | 幅 48 × 高さ 60 の縦長のカプセル |
| 作成ボタン | 48 の円 |

そのため、「＋」の上下がタブバーから 2pt ずつはみ出し、「＋」と作成ボタンの形も違って見える。

**規則**:
- **高さはすべて56にそろえる**: タブの行の高さ = 「＋」の直径 = 作成ボタンの直径 = 56。数値は `ProminentTabBar` の中の定数1か所（例: `static let barHeight: CGFloat = 56`）にまとめ、ほかはそれを参照する。
- **「＋」は直径56の正円**にする（`.glassEffect(…, in: .circle)`）。作成ボタンも直径56の正円にし、隠れているときは「＋」と完全に重なるようにする（SA01 の分割が、同じ形どうしの自然な分かれ方になる）。
- **記号の大きさ**: 「＋」は22pt・`.medium`、作成ボタンは20pt・`.medium`、タブの記号は今の `.subheadline` のまま。
- **間隔**: 画面の左右の余白は12、タブと「＋」の間は10、作成ボタンと「＋」の間は21（オーナー指定）。`GlassEffectContainer` の `spacing` は18のまま。
- タブが4つでも、iPhone 17e（幅375〜390pt程度）で「Ask AI」の文字が切れないこと。切れる場合は、タブの文字を `caption2` に下げる。それでも切れるときは記号だけの表示にする（N05 の仕組みを使う）。
- **受け入れ条件（シミュレータの画面で測る）**:
  - タブの行・「＋」・作成ボタンの高さが同じ。
  - 「＋」と作成ボタンが正円で、中心が縦にそろっている。
  - iPhone 18 Pro と iPhone 17e の両方で、タブ名が切れない。

### BL03 作成ボタンの下にある一覧の行が隠れないようにする
- 作成ボタンは「＋」の overlay なので、`bottomControlsHeight` に高さが入っていない。そのため、一覧を一番下までスクロールしても、最後の行の右端が作成ボタンの下に隠れる。
- **修正**: 作成ボタンを表示しているときだけ、`bottomContentClearance` に 56 + 21 を足す（モデルに `isContextualCreateShown` を持たせるか、`RootTabView` から足す分を渡す）。
- **受け入れ条件**: タスク・ジャーナル・プロジェクトで一番下までスクロールしたとき、最後の行が作成ボタンに隠れない。

### BL04 トーストと再生バーの位置
- Undo トースト: 一覧のタブでは、作成ボタンより上に出す（作成ボタンがあるときは、BL03 で増やした高さの上）。

- **受け入れ条件**: タスク画面でタスクを削除すると、トーストが作成ボタンと重ならずに出る。

### TC01（中）「Memoraで開く」で受け取った音声のコピーが、アプリ内に残り続ける
- `LSSupportsOpeningDocumentsInPlace = false` のため、受け取ったファイルは `Documents/Inbox` にコピーされてから渡される。`importAudio(from:)` で管理フォルダへ取り込んだあとも、この Inbox のコピーが削除されない。取り込むたびに、同じ大きさの容量を無駄に使う。
- **修正**: 取り込みが終わったら（成功しても失敗しても）、URL が自分のアプリの `Documents/Inbox` の中にある場合に限り、そのファイルを削除する。ファイル選択（`fileImporter`）から来た URL は、利用者のファイルなので削除しない。

### TC02（低〜中）録音中に受け取った音声が、アプリが終了すると失われる
- 録音中に受け取った URL は `pendingImportURLs`（メモリ上の配列）に入るだけ。その間にアプリが終了すると、取り込まれないまま Inbox にファイルだけが残る。
- **修正**: 起動時と前面に戻ったときに `Documents/Inbox` を調べ、音声が残っていれば「取り込まれていない音声が n 件あります」と伝えて、取り込むか削除するかを選べるようにする。

### TC03（低〜中）その日の9時を過ぎてから通知をオンにすると、何も起きない
- `TaskReminderScheduler.refresh` は期限日の9:00に通知する。期限が今日のタスクで9時を過ぎてから通知をオンにすると、`fireDate > .now` を満たさないため、何も登録されない。そのことも画面に出ない。
- **修正**: 通知の時刻を選べるようにする（既定は9:00、`TaskEditView` / `AddTaskView` に `DatePicker(displayedComponents: .hourAndMinute)`）。選んだ時刻が過ぎている場合は、Toggle の下に「この時刻は過ぎているため通知されません」と表示する。`MemoraTask` に `reminderTime` を追加する（`decodeIfPresent`、既定は9:00）。
