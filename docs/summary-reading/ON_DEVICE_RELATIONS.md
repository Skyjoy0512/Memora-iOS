# 端末内要約の根拠付き階層

2026-10-24。表示用サンプルだけでなく、端末内要約の実装経路にも理由・条件・影響を渡す。新しい画面やデザインへの置き換えではない。

## 実装範囲

- `OnDeviceSummarizer` の既存の話題抽出で、最大2件／話題の関係候補をガイド生成する。別の生成段階・クラウド要求は追加しない。スキーマと指示は増えるため、トークン数・応答時間・既存のコンテキスト超過再試行回数が変わらないとは保証しない。
- 時刻は従来の発言行を再利用し、検証後に実際のセグメントUUIDへ結び付ける。同じ表示時刻の発言が複数ある場合は曖昧として採用しない。存在しない時刻、UUID、範囲外／非有限の時刻、親の重複、対象発言と異なる引用は拒否する。
- 親は要点または決定事項の1項目と原文内の節に完全一致する5〜80文字。引用は8〜200文字の発言全文とし、末尾の否定・留保・条件を切り落とした部分引用は採用しない。長い／複数行の発言や別発言間の関係は今回は扱わない。日本語の明示的な接続表現も必要とする。
- これは参照整合性と保守的な文字列検査であり、モデルによる決定・因果の意味分類を証明するものではない。接続語だけでは誤分類を完全には防げない。原文全文を残し、公開前に実音声・実モデルによる確認が必要。
- 親の種類（要点／決定）を保持し、同じ文面でも別種類の親へ付け替えない。関係の重複は除き、親ごとの一時索引を使う。永続キャッシュや権限境界の変更はない。
- 組み込み4テンプレートの既存Markdown階層へ子項目を追加し、前回実装した分岐マーク・インライン編集・常時表示PNGを再利用する。概要に渡す中間ノートでは親と全文引用を一体で扱い、文字数上限で引用の末尾だけを切らない。
- カスタム／マーケット用の最終生成スキーマとレイアウトは維持する。中間ノートには根拠を残すが、それらの最終本文の階層出力を保証する変更ではない。
- 既存の保存済み要約は自動生成・上書きしない。SQLiteスキーマ・音声・原文・セグメントID・話者・時刻は変更しない。関係を採用できない場合は既存の平坦な項目を保つ。
- 回帰検査で発見した読み戻しの不具合も修正した。「議事録／詳細議事録」配下の話題名に「決定」が含まれていても、本文の要点を決定事項として登録しない。明示的な決定事項の見出しと既存の太字区分は維持する。

## 検証の境界

`run-summary-reading-checks.sh` に、未接続だった既存の `SummaryLayoutChecks` と、新しい `SummaryRelationChecks` を接続した。本番の検証器・4テンプレートのビルダー・Markdown解析／編集・SQLite再読込を実行する。ホストのSQLite検査は文書の再保存であり、アプリ全体のモデルや生成セッションの実行ではない。

`tests/summary-relations.e2e.ts` は同じ本番ビルダーが出力したフィクスチャを用い、専用Simulator上で読み込み・PNG・全文表示・編集・再起動復元を検査する。固定の検証用発言から関係候補をテストが指定しており、実モデルが抽出した結果ではない。既存のBitrigプレビューのDBには投入しない。

初回ビルド／ホスト検査では連結式の型推論が時間切れとなり、単純なループへ分解した。親の種類を分ける追加検査では話題名の読み戻し不具合を検出し、上記の見出し境界を修正した。初回UI検査は4件中2件成功・2件失敗。文字起こし復元の失敗画面には保存エラーのアラートが残っており、起動時にも失敗注入が作用していたため、保存失敗を確認した後、再起動前に検証用トリガーを解除するようテストを修正した。新しい関係の編集では日本語入力の読戻しに余分な1文字があり、編集値・フォーカスの確定を明示してから入力する検査へ変更した。いずれも最終結果とは分けて記録する。

実モデルの要約精度、代表的な長時間音声、実機の日本語IME／VoiceOver／Reduce Motion、FPS・入力遅延・メモリ・電池の同条件Before/Afterは未検証。改善率は報告しない。
