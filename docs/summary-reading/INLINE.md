# 常時表示サマリーと要約済み音声サンプル

## 変更（2026-10-24）

- 要約タブの先頭に既存のPNGレンダラーによる画像を表示する。本文を折りたたんでも画像は残す。拡大・全文表示・共有確認・一時ファイル削除は既存のシートを利用する。
- 画像は本文・タイトル・日時・プライバシー・ワークスペース世代の一致を確認してから表示する。表示用UUIDの違いだけで画像生成を繰り返さず、変更後は古い画像を表示しない。空の要約、保護中、復元中、許可されない領域には出さない。
- 本文の子箇条書きは既存のLucide分岐マークと字下げで表現する。数値付きリストとチェックボックスは従来どおり。関係は「理由」「条件」「影響」の言葉でも示し、図形だけに依存しない。
- 要約プロンプトでは原文で明示された因果・条件だけを階層化する。既存の要約を推測で書き換えず、追加のAI呼び出しは行わない。表・見出し指定を優先する。
- 抽出時は字下げされた理由・条件を親の決定／行動と一緒に保持し、別の決定／タスクにしない。全面太字の決定を区分見出しと誤認していた問題も修正した。旧形式の既知の区分ラベルは引き続き読める。

## サンプルの開き方

設定 → 診断とプレビュー → **要約済み音声のサンプルを見る**。

「発売準備ミーティング（サンプル）」をSQLiteに1件追加して開く。既存の会議、プロジェクト、タスク、人物、会話、編集中のAsk AI下書きは置き換えない。もう一度選ぶと既存のサンプルを開き、編集済みの内容を初期化しない。保存に失敗した場合は設定画面内に理由を表示し、成功するまで追加・遷移しない。

これは表示確認用の架空データで、音声ファイルは含まず、文字起こし・要約エンジンを実行した結果ではない。サンプル表示を明記し、既存の「サンプルを削除」の対象にも含める。チーム領域・復元中には追加しない。開発用の全件置換ボタンは使わない。

## 検証の区別

- ホスト：要約指示、字下げと元行の対応、親と理由の抽出、太字の決定、旧形式、画像スナップショットの変更検出、保存失敗・再試行・競合の検査。
- Simulator：常時表示、サンプルの追加・保存失敗からの再試行・重複防止・理由の編集・再読込・既存記録の保持・サンプルだけの削除。既存のPNG共有／キャンセル、全文編集、文字起こし整形と下書き復旧も回帰対象。
- 実モデルによる因果構造の出力品質、実音声の文字起こし、実機のVoiceOver操作・メモリ・電池・描画時間は未検証。プロンプト検査と架空データの表示成功を、これらの実行品質の証明にはしない。
- 因果階層の生成指示を追加したのはクラウド要約の `SummaryPrompt.system`。オンデバイスのガイド生成スキーマは変更せず、既存のテンプレート階層を保つ。両方の経路で既存の階層Markdownは同じ分岐マークで表示する。

## 実行結果

ホスト回帰5スイートはすべて成功（`/Volumes/WorkspaceSSD/Development/Temp/memora-summary-inline-quality-20261024/summary.json`）。その後の抽出処理修正も `run-summary-reading-checks.sh` で再検査して成功。

初回UI回帰は要約表示1件・保存復旧2件が成功、サンプル1件は失敗した（`.e2e/regression/summary-inline-20261024/report.json`）。保存失敗の共通通知が設定を閉じ、同じ画面で再試行できないことを検出したため、サンプル操作だけを既存のローカルエラー処理へ変更した。初回の失敗は成功扱いしない。

最終コードのDebugプレビュー成功（`2026-10-24T13-48-13-0c64b66e.log`）、ReleaseのiOS Simulatorビルド成功（`2026-10-24T13-49-56-71b41bd0.log`）。既存の非推奨API等の警告11件は残る。実機での署名・実行確認ではない。

同じ最終アプリで要約表示1件・保存復旧2件が再度成功（`.e2e/regression/summary-inline-final-20261024/report.json`）。その実行のサンプル1件は、ネイティブ遷移中のLibraryと詳細のタイトル重複によりテストの検索が曖昧となって失敗した。検索を可視の詳細タイトルへ限定し、アプリコードは変えずにサンプル検証だけを再実行して成功した（`.e2e/regression/summary-sample-final-20261024/report.json`、1件成功・失敗0・スキップ0、94.22秒）。

サンプル検証では、本番UIからのSQLite追加失敗／再試行、既存記録の保持、自動画像表示、理由のインライン編集と字下げ維持、再オープンと再起動で編集が保持されること、重複しないこと、既存の削除操作でサンプルだけを削除できることまで確認した。テストのモデル呼び出しは0。所要時間は機能テストの時間であり、描画性能の改善値ではない。
