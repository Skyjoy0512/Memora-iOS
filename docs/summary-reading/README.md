## 実装（2026-10-24）

- 要約の共通指示を、結論・影響・根拠・条件・未解決事項が読み分けられる形に更新。提案を決定に変えず、担当・期限・因果を補完しない。重要度順／時系列順、既存テンプレート、編集、履歴を維持する。
- 組み込みの日本語可読性ガイドを [yomiyasu v2.3.0](https://github.com/nanaism/yomiyasu/tree/v2.3.0) に追従。自然な語形と文脈が確かな用語を採用し、数値・否定・条件・確度・引用を保全する。Python解析器や上流のスキル／フックをインストールする変更ではない。MIT表記・既存ライセンスを維持する。
- 「読みやすく表示」は、区切りの明確な文頭フィラーと行端の余白だけを整える可逆な表示。原文・セグメントID・話者・時刻・引用用入力は変更しない。編集は原文で行い、表示設定だけをUserDefaultsに保存する。曖昧な「あの／その／はい／多分」、引用内や文中の言い直し、全大文字の英語略称は削除しない。
- サマリーに「1枚サマリー」の入口を追加。現在保存されている要約本文を既存Markdown抽出器で読み、要旨／決定／アクション／未解決事項をモノトーンのPNGにする。別編集された補助リスト・他の記録・タスクは混ぜない。旧形式の見出しにも対応し、「未決定」を決定と誤分類しない。
- 概要のラベルを識別できない旧形式では、冒頭のまとまった本文をそのまま「本文の抜粋」として使う。本文が存在するのに空の概要としない一方、未知の見出しを決定や合意と意味推定して補完しない。
- PNGは幅1440px、高さは内容に合わせて可変（初版は1440 × 2400固定だった）。各リスト先頭2件・文字数と表示行数に上限がある抜粋であり、件数・長さの省略と全文確認の注意を画像内に明記する。抽出できない欄を「なし／解決済み」と扱わない。任意のカスタム見出しの意味推定は行わない。
- 画像は開いたときだけ端末内で生成。表示中はメモリ上、明示的な共有確認後に限り保護された一時PNGを書き出す。共有終了・キャンセル・画面終了時に一時コピーを削除し、SQLiteや元の音声・添付ファイルには書き込まない。
- 要約・タイトル・日付・プライバシー・記録の削除・復元・保護・ワークスペース世代が変われば、古いプレビューと新規共有を拒否する。個人領域の記録だけが対象。共有は既存のシステムシートで、利用者が宛先／「ファイルに保存」を選ぶ。自動送信・追加API・追加LLM呼び出し・OAuth権限追加・写真ライブラリ権限追加はない。
- 画像を拡大でき、全文タブには既存Markdown描画を再利用したDynamic Type対応のテキストを表示する。既存のインライン編集、Liquid Glassナビゲーション、サイドメニュー、Journalのフラットな内容は維持する。Apple標準の画面構造とアクセシブルな代替テキストを優先した。

## 検証の区別

`tools/checks/run-summary-reading-checks.sh` は本番コードで、テンプレート／要約形式、意味保全例、原文の引用用入力、PNG向け抽出・旧形式・長さ制限・Unicode、スナップショット失効条件を検証する。スナップショットのモデル境界は明示したホスト用ハーネスであり、実機権限の検証ではない。

`tests/summary-reading.e2e.ts` は専用Simulatorを再インストールし、UIで作ったUUIDメモでSQLiteを特定した後、検証用の会議を投入する。既存ユーザーやBitrigプレビューのDBは変更しない。生成モデルを呼ばず、実際のSQLite再読込・画像生成・一時ファイル・共有キャンセル・原文と設定の復元・編集を検証する。画像データのPNG署名と寸法も読む。

スクリーンショットや画像を添付する場合、コミット対象はこの明示的な検証用会議だけとする。既存ユーザーの画面を保存した確認用ファイルはローカルのリポジトリ外に留める。

実モデルによる要約品質の比較、実音声による認識精度・フィラーの誤除去率、実機のFPS／入力遅延／メモリ／電池、共有先への最終保存・外部送信は未検証。既存の保存済み要約は自動で再生成・上書きしない。新しい要約指示は次回の生成に適用する。

## 品質結果

- 環境：Apple Silicon arm64、macOS 27.0.1、iOS Simulator SDK 27.1、Apple Swift 6.4。UIは専用iPhone 18 Pro Max Simulator。実機ではない。
- 最終Debugプレビュー成功：`2026-10-24T12-37-40-fa5056c6.log`。最終Release成功：`2026-10-24T12-37-42-e8c1a6f2.log`。いずれも既存の非推奨API等の警告11件を残す。ログはBitrigの本プロジェクトのBuilds/logsに保存。
- ホスト回帰5スイート（next-generation / design-refresh / background-summary / composer-layout / optimization）成功。ローカル記録：`/Volumes/WorkspaceSSD/Development/Temp/memora-summary-quality-20261024-final/summary.json`。追加したテンプレート由来の機密区分による画像失効・未知の旧形式の本文抜粋は、個別の `run-summary-reading-checks.sh` を再実行して成功。最終Debug／ReleaseとUI E2Eもその追加修正後のコードで実行した。
- 最終E2E：2ファイル・5件成功、失敗0・スキップ0。`summary-reading.e2e.ts` 1件と `native-header.e2e.ts` 4件。ログ・トレースはローカルの `.e2e/regression/summary-reading-legacy-complete-20261024/`。モデル呼び出しなし。
- 実際のSQLite再読込、PNG署名と1440 × 2400寸法、共有シートの表示とキャンセル後の一時コピー削除、本文の編集→新しい画像の全文、フィラー表示→原文編集、表示設定の再起動復元を確認。原文・要約が表示切替で変わらないこともDBで照合。最大Dynamic Typeは専用Simulatorのコンテナを再確認して変更し、元の設定へ復元した。
- 最初の文字起こしチェックは末尾句点を除去する不具合で失敗し、先頭区切りだけを除去するよう修正して再実行成功。最初のE2Eはネイティブのタブ／共有項目をボタンとして探すテストの誤りで失敗し、実際のAXロールに修正して再実行成功。失敗ログを成功に読み替えていない。
- 処理時間・FPS・メモリ・電池の同条件Before/Afterは未計測。高速化率は報告しない。描画は画面を開いたときだけ、PNGは明示的な共有時だけとし、画像解像度・抜粋件数・長さを固定上限で抑える。
