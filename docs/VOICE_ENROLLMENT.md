# 自分の声の登録と録音の安定性

設定 → 文字起こし → 自分の声から、10〜30秒の音声サンプルを録音し、確認して登録できる。再登録は保存に成功した後で以前のサンプルを置き換える。短すぎるサンプルやほとんど音の入っていないサンプルは登録しない。これは音量の確認であり、発話や本人の認証ではない。

サンプルはApplication Support/VoiceSamples内の音声ファイル、登録情報はSQLiteに保存する。ファイル名だけを参照し、音声をUserDefaultsやレコード内に埋め込まない。端末のバックアップから音声フォルダーを除外し、Memoraのバックアップ・共有パッケージにも含めない。クラウド、AI、チームへ送信しない。別の端末への移行時は再登録が必要。

画面を閉じたときに未登録サンプルを破棄する。クラッシュなどで残った未登録サンプルは、SQLiteの正常な読み込みを確認できた次回起動時に削除する。中断・バックグラウンド移行時はサンプル録音を止める。

**自動話者識別は未実装。** 登録サンプルを使う本人照合モデルはまだ接続していない。現時点ではサンプルを保存・再生・削除できるだけで、文字起こしの話者名や確度は変更しない。

## 録音開始の修正

- 音声セッションの停止コールバック登録をObservationの対象外にした。ホストで見つかった2026-10-09のクラッシュログは、SpeechInputServiceの生成中にこの登録がSwiftUIの更新を再発させ、AttributeGraphの検査に失敗していた。これは実機のクラッシュログではないので、今回のiPhoneの原因と断定しない。
- 録音は録音用のdefaultモードを使い、入力の有無、prepareToRecordの結果を確認する。
- 録音の復旧情報を先に同期保存してから、Live Activityとリアルタイム文字起こしを開始する。
- リアルタイム文字起こしは入力形式を確認し、端末の形式をSpeechAnalyzerに対応する形式へ変換する。マイクの再利用バッファをそのまま非同期処理へ渡さない。キューが処理に追いつかない場合、表示だけを止め、録音は継続する。
- 入力タップは一度だけ外し、文字起こしのエンジンを止めてから録音の音声セッションを解放する。
- 通常の録音は声の登録より優先する。録音、再生、Ask AI音声入力と声の登録が同時にマイクを奪い合わない。

## 実機での確認

対象の申告はiPhone 14 Pro Max、iOS 26、内蔵マイク。実機のクラッシュログは未取得。

録音中の文字起こしをオン／オフにしてそれぞれ録音開始・停止・再開を確認する。初回の権限確認、着信、画面ロック、録音中の声登録拒否、再登録のキャンセル、再起動後の再生・削除も確認する。まだ落ちる場合は、その発生時刻のMemoraの.ipsログで原因を特定する。
